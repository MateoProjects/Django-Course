Unitat 02 · Curs de Django

Configuració i Settings

Tot el que Django necessita saber sobre el teu projecte viu a settings.py.

En aquesta unitat aprendràs:

  • Els paràmetres principals de settings.py i per a què serveix cadascun
  • Gestionar variables sensibles amb python-decouple i un fitxer .env
  • Crear una estructura multi-entorn: base.py, dev.py, prod.py, test.py
  • Configurar la base de dades amb dj-database-url
  • Bones pràctiques de seguretat en la configuració

◆ L'arxiu settings.py — anatomia completa

El fitxer settings.py és el cervell de la configuració de Django. Conté variables en majúscules que Django llegeix en arrencar per configurar cada subsistema: la base de dades, les apps instal·lades, el middleware, els templates, la cache, els correus, etc. Tot és Python pur, cosa que permet lògica condicional, importació d'altres mòduls i variables d'entorn.

SECRET_KEY
Clau criptogràfica per a signatures, sessions i CSRF. Mai exposes al repositori.
DEBUG
True en dev (pàgina d'error detallada). SEMPRE False en producció.
ALLOWED_HOSTS
Llista de dominis vàlids. En producció: ['bibliapp.com', 'www.bibliapp.com'].
INSTALLED_APPS
Apps actives al projecte. Afegeix cada nova app aquí per activar ORM, admin, signals.
MIDDLEWARE
Capa d'interceptors de peticions/respostes. L'ordre importa molt.
DATABASES
Configuració de bases de dades. Per defecte SQLite; en producció PostgreSQL.
STATIC_URL / MEDIA_URL
URLs base per a fitxers estàtics i pujades d'usuaris.
AUTH_USER_MODEL
Model d'usuari personalitzat. Ha de definir-se ABANS de la primera migració.
DEFAULT_AUTO_FIELD
Tipus del camp id automàtic: BigAutoField (int 64 bits, recomanat).
  • INSTALLED_APPS — cada string és un camí Python a la classe AppConfig de l'app, o simplement el nom de l'app
  • MIDDLEWARE — es processa de dalt a baix per a les peticions i de baix a dalt per a les respostes
  • TEMPLATES — configura el motor de templates, els directoris de cerca i els context processors
  • TIME_ZONE — zona horària del servidor; independentment d'això, recomanem guardar dates en UTC (USE_TZ = True)
⚠️ Seguretat crítica

Mai posis SECRET_KEY, contrasenyes de base de dades, claus d'API ni cap secret directament al fitxer settings.py si el repositori és accessible. Usa sempre variables d'entorn o un fitxer .env exclòs del repositori via .gitignore.

◆ Variables sensibles amb python-decouple

La llibreria python-decouple separa la configuració sensible del codi font. Llegeix variables d'un fitxer .env (o de les variables d'entorn del sistema) i les exposa amb tipus correctes i valors per defecte. Això permet tenir el mateix codi en tots els entorns i canviar el comportament només canviant el .env.

dj-database-url complementa decouple: converteix una URL de base de dades (format estàndard de serveis com Heroku, Railway o Render) al diccionari que Django espera a DATABASES['default']. Una sola variable d'entorn configura tota la connexió.

  • config('NOM', default='valor', cast=bool) — llegeix variable amb tipus i valor per defecte
  • Csv() — cast especial per a llistes separades per comes: ALLOWED_HOSTS = config('HOSTS', cast=Csv())
  • DATABASE_URL=postgres://user:pass@host:5432/db — format estàndard de URL de base de dades
  • dj_database_url.config(conn_max_age=600) — parsing automàtic amb connexions persistents
📌 Fitxer .env

El fitxer .env mai ha d'entrar al repositori. Afegeix-lo al .gitignore però proporciona sempre un .env.example amb totes les variables necessàries però sense valors reals, perquè el pròxim desenvolupador sàpiga quines variables configurar.

◆ Arquitectura multi-entorn de settings

A mesura que el projecte creix, un sol settings.py es torna difícil de gestionar: dev usa SQLite i DEBUG=True, producció usa PostgreSQL i configuració de seguretat estricta, i els tests necessiten una base de dades en memòria. La solució estàndard és dividir els settings en múltiples fitxers amb herència Python.

  • settings/base.py — configuració comuna a tots els entorns: INSTALLED_APPS, MIDDLEWARE, TEMPLATES, AUTH
  • settings/dev.py — hereda base, activa DEBUG, usa SQLite, pot incloure django-debug-toolbar
  • settings/prod.py — hereda base, DEBUG=False, PostgreSQL, HTTPS, HSTS, caché Redis
  • settings/test.py — hereda base, base de dades en memòria, password hasher ràpid, sense correus reals
  • DJANGO_SETTINGS_MODULE — variable d'entorn que indica quin fitxer de settings usar
🔮 Referència real

Aquesta arquitectura és exactament la que usa MediNetNode (config/settings/base.py, dev.py, prod.py, test.py). El conftest.py de pytest configura automàticament DJANGO_SETTINGS_MODULE=config.settings.test.

Python config/settings/base.py 
"""
Settings base de bibliapp.
Compartit per tots els entorns: dev, prod, test.
Mai executar directament — sempre heretar des d'un settings específic.
"""
from pathlib import Path
from decouple import config, Csv

# BASE_DIR apunta a l'arrel del projecte (on viu manage.py)
BASE_DIR = Path(__file__).resolve().parent.parent.parent

# ── Seguretat ──────────────────────────────────────────────────────────
# La SECRET_KEY mai ha d'estar hardcodejada; ve del .env
SECRET_KEY = config('SECRET_KEY')

# ── Apps instal·lades ──────────────────────────────────────────────────
INSTALLED_APPS = [
    # Apps internes de Django
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    # Apps del projecte bibliapp
    'books',
    'users',
]

# ── Middleware (l'ordre importa) ───────────────────────────────────────
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    'django.middleware.csrf.CsrfViewMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.contrib.messages.middleware.MessageMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
]

ROOT_URLCONF = 'config.urls'

# ── Templates ──────────────────────────────────────────────────────────
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        # Django cerca templates a la carpeta templates/ de cada app
        # i a les carpetes llistades aquí
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.debug',
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]

WSGI_APPLICATION = 'config.wsgi.application'

# ── Internacionalització ───────────────────────────────────────────────
LANGUAGE_CODE = 'ca'          # Català
TIME_ZONE = 'Europe/Madrid'   # Zona horària (les dates es guarden en UTC)
USE_I18N = True
USE_TZ = True                 # Sempre activat: evita problemes de timezone

# ── Fitxers estàtics ───────────────────────────────────────────────────
STATIC_URL = '/static/'
STATIC_ROOT = BASE_DIR / 'staticfiles'   # collectstatic posa aquí els fitxers
STATICFILES_DIRS = [BASE_DIR / 'static']

MEDIA_URL = '/media/'
MEDIA_ROOT = BASE_DIR / 'media'

# ── Camps automàtics ───────────────────────────────────────────────────
# BigAutoField: id de 64 bits, evita desbordament en taules grans
DEFAULT_AUTO_FIELD = 'django.db.models.BigAutoField'

# ── Model d'usuari ─────────────────────────────────────────────────────
# Ha d'estar definit ABANS de crear la primera migració
# AUTH_USER_MODEL = 'users.CustomUser'  # descomenta quan tinguis l'app users
Python config/settings/dev.py 
"""
Settings de desenvolupament local.
Uso: DJANGO_SETTINGS_MODULE=config.settings.dev python manage.py runserver
"""
from .base import *  # noqa: F401,F403 — importa tot de base
from decouple import config

DEBUG = True

# En dev acceptem qualsevol host; en prod serà el domini real
ALLOWED_HOSTS = ['localhost', '127.0.0.1', '0.0.0.0']

# SQLite per a dev: sense configuració extra, fitxer local
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}

# Missatges de correu a la consola en lloc d'enviar-los de debò

Python config/settings/prod.py 
"""
Settings de producció.
Uso: DJANGO_SETTINGS_MODULE=config.settings.prod
Les variables sensibles vénen de les variables d'entorn del servidor.
"""
from .base import *  # noqa: F401,F403
import dj_database_url
from decouple import config, Csv

DEBUG = False

# En producció, dominis explícits; mai '*'
ALLOWED_HOSTS = config('ALLOWED_HOSTS', cast=Csv())

# Base de dades via URL d'entorn (PostgreSQL a Render, Railway, etc.)
# Exemple: DATABASE_URL=postgresql://user:pass@host:5432/bibliapp_prod
DATABASES = {
    'default': dj_database_url.config(
        default=config('DATABASE_URL'),
        conn_max_age=600,      # connexions persistents: millora el rendiment
        conn_health_checks=True,
    )
}

# ── Seguretat HTTPS ────────────────────────────────────────────────────
SECURE_SSL_REDIRECT = True                  # Redirigeix HTTP → HTTPS
SECURE_HSTS_SECONDS = 31536000             # HSTS: 1 any
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True
SESSION_COOKIE_SECURE = True               # Cookie de sessió només per HTTPS
CSRF_COOKIE_SECURE = True                  # Cookie CSRF només per HTTPS
SECURE_BROWSER_XSS_FILTER = True
X_FRAME_OPTIONS = 'DENY'

# ── Cache amb Redis ────────────────────────────────────────────────────
CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.redis.RedisCache',
        'LOCATION': config('REDIS_URL', default='redis://localhost:6379/0'),
    }
}

# ── Correus reals ──────────────────────────────────────────────────────
EMAIL_BACKEND = 'django.core.mail.backends.smtp.EmailBackend'
EMAIL_HOST = config('EMAIL_HOST')
EMAIL_PORT = config('EMAIL_PORT', cast=int, default=587)
EMAIL_USE_TLS = True
EMAIL_HOST_USER = config('EMAIL_HOST_USER')
EMAIL_HOST_PASSWORD = config('EMAIL_HOST_PASSWORD')
Python config/settings/test.py 
"""
Settings per als tests automatitzats.
pytest-django el carrega automàticament via conftest.py:
  DJANGO_SETTINGS_MODULE = 'config.settings.test'
"""
from .base import *  # noqa: F401,F403

DEBUG = False
ALLOWED_HOSTS = ['testserver']

# Base de dades en memòria: tests molt més ràpids
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': ':memory:',
    }
}

# Hasher de contrasenya simple: els tests no necessiten seguretat criptogràfica
PASSWORD_HASHERS = ['django.contrib.auth.hashers.MD5PasswordHasher']

# Sense missatges de correu als tests
EMAIL_BACKEND = 'django.core.mail.backends.locmem.EmailBackend'

# Desactiva la cache als tests per evitar interferències entre casos
CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.dummy.DummyCache',
    }
}

🏋️ Exercici Pràctic bibliapp

Configuració de múltiples bases de dades

Django permet configurar diverses bases de dades simultàniament, útil per separar dades d'usuaris de dades d'aplicació. Afegirem una segona base de dades dedicada als logs d'auditoria i un router que hi enviï automàticament els models correctes.

Tasques:

  1. Afegeix una segona base de dades logs_db a settings/dev.py (SQLite a logs.sqlite3)
  2. Crea un fitxer bibliapp/routers.py amb un LogsRouter que enviï els models de l'app audit a logs_db
  3. Registra el router a DATABASE_ROUTERS a base.py
Python Codi inicial — completa els TODO 
# bibliapp/settings/dev.py
from .base import *
DEBUG = True
DATABASES = {
    'default': {'ENGINE': 'django.db.backends.sqlite3', 'NAME': BASE_DIR / 'db.sqlite3'},
    # TODO: afegir 'logs_db' apuntant a logs.sqlite3
}

# bibliapp/routers.py
class LogsRouter:
    # TODO: implementar db_for_read, db_for_write, allow_migrate
    # Els models de l'app 'audit' han d'anar a 'logs_db'
    pass
💡 El router ha de comprovar model._meta.app_label == 'audit' per saber si el model pertany a l'app d'auditoria.

Resultat esperat:

python manage.py migrate --database=logs_db crea les taules d'audit a logs.sqlite3 sense afectar la base de dades principal.

👁 Veure solució
Python Solució completa 
# bibliapp/settings/dev.py
from .base import *
DEBUG = True
DATABASES = {
    'default': {'ENGINE': 'django.db.backends.sqlite3', 'NAME': BASE_DIR / 'db.sqlite3'},
    'logs_db': {'ENGINE': 'django.db.backends.sqlite3', 'NAME': BASE_DIR / 'logs.sqlite3'},
}

# bibliapp/routers.py
class LogsRouter:
    route_app_labels = {'audit'}

    def db_for_read(self, model, **hints):
        if model._meta.app_label in self.route_app_labels:
            return 'logs_db'
        return None

    def db_for_write(self, model, **hints):
        if model._meta.app_label in self.route_app_labels:
            return 'logs_db'
        return None

    def allow_migrate(self, db, app_label, model_name=None, **hints):
        if app_label in self.route_app_labels:
            return db == 'logs_db'
        return db == 'default'

# bibliapp/settings/base.py — afegir:
DATABASE_ROUTERS = ['bibliapp.routers.LogsRouter']
