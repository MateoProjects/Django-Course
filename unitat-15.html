Signals de Django

Desacobla components de la teva aplicació: reacciona automàticament a esdeveniments del model sense modificar-ne el codi.

En aquesta unitat aprendràs:

  • Entendre el patró observador que implementen els signals de Django
  • Usar @receiver amb post_save, pre_save, post_delete i altres signals built-in
  • Evitar connexions dobles amb dispatch_uid i saber on col·locar els signals a apps.py
  • Crear signals personalitzats i emetre'ls des del codi de l'aplicació

◆ Signals built-in: post_save, pre_save, post_delete

Un signal és un mecanisme de notificació desacoblat: quan passa alguna cosa en un punt del codi (el sender), Django avisa automàticament tots els receivers que s'hi han subscrit, sense que el sender sàpiga res dels receivers. Això permet afegir comportament reactiu (crear perfils, enviar notificacions, actualitzar comptadors) sense modificar el model original.

Flux d'un signal post_save

Prestec.save()
→
post_save
sender=Prestec
→
actualitzar_disponibilitat()

El decorador @receiver(signal, sender=Model) és la manera més neta de subscriure una funció a un signal. El paràmetre sender limita les notificacions al model concret; sense ell, la funció rebria notificacions de tots els models que llancin aquell signal.

  • post_save — s'emet després que es guarda un objecte (tant si és nou com si és una actualització). El paràmetre created=True indica si és una creació nova.
  • pre_save — s'emet abans de guardar. Útil per modificar l'objecte o validar-lo (però millor usar clean() per a validació).
  • post_delete — s'emet després d'esborrar. L'objecte ja no existeix a la base de dades, però l'instància Python encara és accessible.
  • pre_delete — s'emet abans d'esborrar. Útil per alliberar recursos associats (fitxers, registres externs).
  • m2m_changed — s'emet quan canvia una relació ManyToManyField. Té les accions pre_add, post_add, pre_remove, post_remove.
  • sender — el model (classe, no instància) que emet el signal. Permet filtrar per model concret.
  • instance — l'objecte concret que ha desencadenat el signal (p.ex. el Prestec que s'acaba de crear).
  • created — paràmetre de post_save: True si l'objecte s'acaba de crear, False si s'ha actualitzat.
  • **kwargs — captura tots els altres paràmetres que Django pot enviar en el futur. Sempre cal incloure'ls a la signatura del receiver.
⚠️ Atenció amb post_save

Dins d'un receiver de post_save, si crides instance.save() sense precaució, es torna a emetre el signal i caus en un bucle infinit. Usa update_fields=['camp'] per actualitzar camps concrets, o comprova created per limitar l'execució.

Python signals.py — crear UserProfile automàticament (patró de MediNetNode) 
from django.db.models.signals import post_save
from django.contrib.auth import get_user_model
from django.dispatch import receiver
from .models import PerfilLector

User = get_user_model()


@receiver(post_save, sender=User, dispatch_uid='crear_perfil_lector')
def crear_perfil_lector(sender, instance, created, **kwargs):
    """
    Cada vegada que es crea un nou User, creem automàticament el seu PerfilLector.
    Usem dispatch_uid per garantir que el receiver es connecta una sola vegada,
    fins i tot si el mòdul s'importa diverses vegades (problema freqüent).
    """
    if created:
        # Creem el perfil només quan l'usuari és NOU (created=True)
        PerfilLector.objects.create(
            usuari=instance,
            nom=instance.first_name or instance.username,
            email=instance.email,
        )


@receiver(post_save, sender=User, dispatch_uid='sincronitzar_perfil_lector')
def sincronitzar_perfil_lector(sender, instance, created, **kwargs):
    """
    Quan s'actualitza un User existent, sincronitzem l'email al perfil.
    dispatch_uid diferent del receiver anterior per evitar col·lisions.
    """
    if not created:
        # update_fields evita re-emetre el signal (no crida .save() complet)
        try:
            instance.perfillector.email = instance.email
            instance.perfillector.save(update_fields=['email'])
        except PerfilLector.DoesNotExist:
            # Si per algun motiu no existeix el perfil, el creem ara
            PerfilLector.objects.create(
                usuari=instance,
                nom=instance.first_name or instance.username,
                email=instance.email,
            )

◆ dispatch_uid, on col·locar signals i signals personalitzats

El problema més comú amb els signals és la connexió doble: si el mòdul on defines el receiver s'importa dues vegades (cosa que passa fàcilment en Django), el receiver s'executa dues vegades per cada signal. La solució és el paràmetre dispatch_uid: una cadena única que garanteix que el receiver es registra una sola vegada, sigui quantes vegades s'importi el mòdul.

El lloc correcte per importar els signals és el mètode ready() de la classe AppConfig a apps.py. Django crida ready() un cop carregades totes les aplicacions, garantint que els models existeixen. Importar signals al nivell de mòdul (fora de ready()) pot causar errors d'importació circular.

Quan cap signal built-in s'ajusta al teu cas d'ús, pots crear signals personalitzats instanciant Signal(). Després els emets amb signal.send(sender=Classe, **kwargs) des del punt del codi on passa l'event, i els receivers s'hi subscriben amb @receiver com sempre.

  • dispatch_uid='cadena_única' — paràmetre de @receiver (o de signal.connect()) que evita duplicats. La cadena ha de ser única a tot el projecte.
  • AppConfig.ready() — lloc on importar els signals. S'executa un cop Django ha carregat tots els models.
  • Signal() — classe per crear signals personalitzats. Importar des de django.dispatch.
  • signal.send(sender, **kwargs) — emet el signal sincrònament. Retorna una llista de tuples (receiver, return_value).
  • signal.send_robust(sender, **kwargs) — com send() però captura excepcions dels receivers perquè no trenquin el flux principal.
  • signal.disconnect(receiver, sender) — desconnecta un receiver (útil als tests per aïllar comportament).
📌 Signals als tests

Als tests, de vegades vols desactivar els signals perquè no interfereixin. Usa signal.disconnect() al setUp i signal.connect() al tearDown, o el context manager from unittest.mock import patch per simular el comportament del receiver.

Python signals.py — signal sobre Prestec + signal personalitzat 
from django.db.models.signals import post_save
from django.dispatch import receiver, Signal
from .models import Prestec, Llibre

# --- Signal personalitzat ---
# Creem un signal que s'emetrà quan un préstec es marqiu com a retornat.
# Permet que altres mòduls reaccionin (notificació, estadística) sense acoblar-se.
llibre_retornat = Signal()  # podria rebre: sender, prestec, llibre


@receiver(post_save, sender=Prestec, dispatch_uid='actualitzar_disponibilitat_prestec')
def actualitzar_disponibilitat_prestec(sender, instance, created, **kwargs):
    """
    Quan es guarda un Prestec:
    - Si és NOU → el llibre passa a no disponible
    - Si s'ACTUALITZA i retornat=True → el llibre torna a estar disponible
      i s'emet el signal personalitzat 'llibre_retornat'
    """
    llibre = instance.llibre  # el Llibre associat al préstec

    if created:
        # Nou préstec: bloquejar el llibre
        # Usem update() per evitar re-emetre signals del model Llibre
        Llibre.objects.filter(pk=llibre.pk).update(disponible=False)

    else:
        # Actualització d'un préstec existent
        if instance.retornat:
            # El préstec s'ha marcat com a retornat: alliberar el llibre
            Llibre.objects.filter(pk=llibre.pk).update(disponible=True)

            # Emetre el signal personalitzat per avisar altres components
            # send_robust captura excepcions dels receivers per no bloquejar el flux
            llibre_retornat.send_robust(
                sender=Prestec,
                prestec=instance,
                llibre=llibre,
            )


@receiver(llibre_retornat, dispatch_uid='log_retorn_llibre')
def log_retorn_llibre(sender, prestec, llibre, **kwargs):
    """
    Receiver del signal personalitzat: registra el retorn al log.
    En un cas real podria enviar un email de confirmació al lector.
    """
    import logging
    logger = logging.getLogger(__name__)
    logger.info(
        "Llibre retornat: '%s' per %s %s",
        llibre.titol,
        prestec.lector.nom,
        prestec.lector.cognom,
    )

from django.apps import AppConfig


class BibliaappConfig(AppConfig):
    default_auto_field = 'django.db.models.BigAutoField'
    name = 'bibliapp'
    verbose_name = 'Biblioteca'

    def ready(self):

        Django crida ready() un cop tots els models estan carregats.
        És el lloc correcte per importar els signals i evitar:
        - Errors d'importació circular (els models ja existeixen)
        - Connexions duplicades (ready() s'executa una sola vegada)
        """
        # L'import executa els decoradors @receiver, connectant els signals
        import bibliapp.signals  # noqa: F401
🔮 Avançat: signals vs. save()

Els signals són potents però fan el flux de l'aplicació més difícil de seguir, ja que el comportament és implícit. Per a lògica simple i directa, sobreescriure save() al model és més explícit i fàcil de testar. Reserva els signals per a comportament verament desacoblat: quan el receiver pertany a una aplicació diferent del sender, o quan diversos receivers independents han de reaccionar al mateix event.

# books/signals.py
from django.db.models.signals import post_save
from django.dispatch import receiver
from .models import Prestec, Llibre

@receiver(post_save, sender=Prestec)
def actualitzar_disponibilitat_llibre(sender, instance, created, **kwargs):
    """Actualitza la disponibilitat del Llibre quan canvia l'estat del Prestec."""
    llibre = instance.llibre
    if created and instance.estat == 'actiu':
        Llibre.objects.filter(pk=llibre.pk).update(disponible=False)
    elif instance.estat == 'retornat':
        Llibre.objects.filter(pk=llibre.pk).update(disponible=True)

PythonSolució completa
# books/signals.py
import logging
from django.dispatch import Signal, receiver
from django.db.models.signals import post_save

logger = logging.getLogger(__name__)

prestec_vençut = Signal()

@receiver(post_save, sender='books.Prestec')
def detectar_vençut(sender, instance, **kwargs):
    if instance.estat == 'vençut':
        prestec_vençut.send(sender=sender, prestec=instance)

@receiver(prestec_vençut)
def avisar_vençut(sender, prestec, **kwargs):
    logger.warning(
        f"PRÉSTEC VENÇUT: '{prestec.llibre.titol}' · "
        f"Lector: {prestec.lector} · "
        f"Vencia: {prestec.data_retorn_prevista}"
    )
