URLs i Routing

Com Django mapeja les adreces web a les funcions vista: el sistema de routing expressiu i flexible de Django.

En aquesta unitat aprendràs:

  • Definir URLpatterns amb path(), paràmetres tipats i include()
  • Organitzar les URLs per app amb app_name i namespaces
  • Generar URLs dinàmicament amb reverse() i el tag {% url %}
  • Usar re_path() per a patrons d'URL complexos amb expressions regulars

◆ urlpatterns, path() i paràmetres d'URL

Django processa cada petició HTTP buscant la primera coincidència a la llista urlpatterns del fitxer urls.py principal. Quan troba una coincidència, crida la vista associada passant-li els paràmetres capturats de l'URL com a arguments de la funció.

La funció path() és la manera moderna i recomanada de definir URLs. Usa convertidors de tipus que validen i converteixen automàticament els segments de l'URL:

  • <int:pk> — captura un enter positiu i el passa com a int; rebutja strings o negatius
  • <str:nom> — captura qualsevol cadena sense barres; és el convertidor per defecte
  • <slug:slug> — captura cadenes amb lletres, números, guions i guions baixos (mon-llibre-2024)
  • <uuid:id> — captura un UUID en format estàndard i el converteix a uuid.UUID
  • <path:ruta> — com str però inclou barres; útil per a rutes de fitxers

La funció include() permet delegar un grup d'URLs a un altre fitxer urls.py, normalment el de l'app. Això manté el fitxer principal net i fa les apps reutilitzables. El prefix de ruta s'afegeix automàticament a totes les URLs incloses.

  • include('books.urls') — inclou totes les URLs de l'app books
  • include('books.urls', namespace='books') — inclou amb namespace (requereix app_name a l'app)
  • re_path(r'^books/(?P<pk>\d+)/$', vista) — URL amb expressió regular; (?P<nom>patró) captura grup amb nom
📌 Conversor personalitzat

Pots crear convertidors propis subclassant i registrant-los amb register_converter(). Per exemple, un convertidor any_any que validi que el número tingui 4 dígits i estigui entre 1900 i 2100.

# ─── bibliapp/urls.py (fitxer principal del projecte) ───────────────────────

from django.contrib import admin
from django.urls import path, include
from django.conf import settings
from django.conf.urls.static import static

urlpatterns = [
    path('admin/', admin.site.urls),

    # Deleguem totes les URLs que comencen per 'books/' a l'app books.
    # El namespace 'books' permet usar {% url 'books:llista' %} als templates.
    path('books/', include('books.urls', namespace='books')),

    # App de préstecs amb el seu propi prefix
    path('prestecs/', include('loans.urls', namespace='loans')),

    # Autenticació integrada de Django (login, logout, canvi contrasenya)
    path('accounts/', include('django.contrib.auth.urls')),
]

# En mode DEV, Django serveix els fitxers media directament.
# En producció, ho fa el servidor web (nginx, etc.).
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)


# ─── books/urls.py (URLs de l'app books) ────────────────────────────────────

from django.urls import path
from . import views

# app_name és obligatori per poder usar namespaces amb include()
app_name = 'books'

urlpatterns = [
    # Llista de tots els llibres: /books/
    path('', views.llistar_llibres, name='llista'),

    # Detall d'un llibre per pk: /books/42/
    path('/', views.detall_llibre, name='detall'),

    # Formulari de creació: /books/nou/
    path('nou/', views.crear_llibre, name='crear'),

    # Formulari d'edició: /books/42/editar/
    path('/editar/', views.actualitzar_llibre, name='editar'),

    # Acció d'esborrat (només POST): /books/42/esborrar/
    path('/esborrar/', views.esborrar_llibre, name='esborrar'),

    # URL amb slug per a SEO: /books/el-senyor-dels-anells/
    path('/', views.detall_per_slug, name='detall-slug'),
]

◆ reverse(), {% url %} i organització d'URLs

Hardcodejar URLs als templates i al codi Python és una mala pràctica: si canvies un patró, has de buscar i canviar totes les referències. Django ofereix dues eines per generar URLs dinàmicament a partir del nom de la vista:

  • reverse('books:detall', args=[pk]) — retorna la URL com a string des de codi Python; és l'invers de la resolució d'URL
  • reverse('books:detall', kwargs={'pk': pk}) — equivalent però usant kwargs en lloc d'args positionals
  • {% url 'books:detall' pk=llibre.pk %} — el tag equivalent als templates Django
  • {% url 'books:llista' %}?cerca=django — pots afegir query strings manualment darrere del tag
  • NoReverseMatch — excepció que llença Django si el nom no existeix o els paràmetres no coincideixen

Per organitzar bé les URLs en projectes grans, segueix aquestes convencions:

  • Cada app té el seu propi urls.py amb app_name declarat
  • El fitxer principal del projecte només fa include(), mai defineix URLs d'apps directament
  • Els noms de les URLs dins d'una app segueixen el patró: llista, detall, crear, editar, esborrar
  • Als templates, sempre usar el namespace: {% url 'books:llista' %} mai {% url 'llista' %}
  • El mètode get_absolute_url() del model usa reverse() per retornar la URL canònica de l'objecte
⚠️ Trampa freqüent

Si uses include('books.urls', namespace='books') al fitxer principal però no declares app_name = 'books' a books/urls.py, Django llença un error en arrencar. El namespace al include() i l'app_name han d'existir tots dos.

Python reverse() al model + {% url %} al template + re_path() 
# ─── books/models.py ────────────────────────────────────────────────────────

from django.db import models
from django.urls import reverse
from django.utils.text import slugify


class Llibre(models.Model):
    titol = models.CharField(max_length=300)
    slug  = models.SlugField(unique=True, blank=True)
    autor = models.ForeignKey('Autor', on_delete=models.CASCADE)

    def save(self, *args, **kwargs):
        # Generem el slug automàticament del títol si no n'hi ha
        if not self.slug:
            self.slug = slugify(self.titol)
        super().save(*args, **kwargs)

    def get_absolute_url(self):
        """URL canònica del llibre. Usada per redirect(llibre) i a l'admin."""
        return reverse('books:detall', kwargs={'pk': self.pk})

    def get_slug_url(self):
        """URL amb slug per a millor SEO."""
        return reverse('books:detall-slug', kwargs={'slug': self.slug})


# ─── Exemple de re_path() per a patrons avançats ────────────────────────────

from django.urls import re_path
from . import views as book_views

# re_path() amb expressió regular nomenada:
# coincideix amb /arxiu/2024/, /arxiu/1999/ però NO /arxiu/99/ (cal 4 dígits)
url_arxiu = re_path(
    r'^arxiu/(?P<any>\d{4})/$',
    book_views.arxiu_per_any,
    name='arxiu',
)

Django 4.0+ ofereix path() amb convertidors que substitueixen completament re_path() per als casos comuns. Reserva re_path() per a patrons que realment no pots expressar amb convertidors, com validació de format de data o ISBNs.

◆ Resum de la unitat

Funcions de routing

  • path() — URL amb convertidors
  • re_path() — URL amb regex
  • include() — delegar a app
  • reverse() — URL des de codi
  • {% url %} — URL des de template

Convertidors de path

  • <int:pk> — enter positiu
  • <str:nom> — cadena sense /
  • <slug:slug> — slug ASCII
  • <uuid:id> — UUID tipat
  • <path:ruta> — cadena amb /
