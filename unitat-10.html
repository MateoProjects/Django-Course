Context Processors

Injecta dades globals a tots els templates sense repetir codi a cada vista

En aquesta unitat aprendràs:

  • Entendre quin problema resolen els context processors
  • Crear un context processor propi a books/context_processors.py
  • Registrar-lo a TEMPLATES['OPTIONS']['context_processors'] de settings
  • Conèixer els context processors built-in de Django i les seves variables

◆ Què és un context processor i per a què serveix

Quan renderitzem un template amb render(request, 'template.html', context), el diccionari context que passem només és disponible per a aquell template concret. Si volem que una variable (per exemple, el nombre de notificacions pendents de l'usuari) sigui disponible a tots els templates de l'aplicació, hauríem de repetir el mateix codi a cada vista. Això és exactament el problema que solucionen els context processors.

Un context processor és simplement una funció Python que rep la petició (request) i retorna un diccionari. Django crida automàticament tots els context processors registrats en cada renderització de template i combina els seus diccionaris amb el context que la vista ha passat explícitament. El resultat final és el context complet disponible al template.

  • def nom_processor(request): — signatura obligatòria: rep request, retorna dict
  • return {'clau': valor} — les claus del diccionari es converteixen en variables de template
  • TEMPLATES['OPTIONS']['context_processors'] — llista a settings.py on es registren
  • S'executen en cada petició que renderitza un template, de forma automàtica
  • Si una clau existeix tant al context del processor com al de la vista, la de la vista guanya
⚠️ Rendiment

Els context processors s'executen en cada petició, incloent les pàgines d'error. Evita fer consultes a la base de dades costoses sense cache. Per a dades que canvien poc, usa cache.get_or_set() (veure Unitat 16). Un context processor lent alentirà tota l'aplicació.

Python books/context_processors.py 
from books.models import Prestec


def prestecs_actius_lector(request):
    """
    Injecta el nombre de préstecs actius de l'usuari autenticat.
    Disponible a tots els templates com: {{ prestecs_actius_count }}

    Retornem 0 si l'usuari no està autenticat per evitar errors
    de consulta contra un usuari anònim.
    """
    if not request.user.is_authenticated:
        return {'prestecs_actius_count': 0}

    # Comptem en comptes de carregar tots els objectes:
    # count() fa un COUNT(*) SQL, molt més eficient que len(queryset)
    count = Prestec.objects.filter(
        lector__usuari=request.user,
        retornat=False
    ).count()

    return {'prestecs_actius_count': count}


def configuracio_biblioteca(request):
    """
    Injecta la configuració global de la biblioteca.
    Útil per mostrar el nom o el logotip a la capçalera sense
    haver-lo de passar des de cada vista.
    """
    from django.conf import settings

    return {
        'biblioteca_nom':  getattr(settings, 'BIBLIOTECA_NOM', 'Biblioteca'),
        'biblioteca_email': getattr(settings, 'BIBLIOTECA_EMAIL', ''),
        'max_prestecs':    getattr(settings, 'MAX_PRESTECS_PER_LECTOR', 3),
    }

◆ Registre a settings i context processors built-in

Per activar un context processor hem d'afegir el seu path Python complet (com a string) a la clau 'context_processors' dins de TEMPLATES[0]['OPTIONS'] a settings.py. Django ve amb quatre context processors activats per defecte en un projecte nou, cadascun aportant un conjunt de variables útils a tots els templates.

  • django.template.context_processors.request — aporta request (accés a la petició, cookies, sessió)
  • django.contrib.auth.context_processors.auth — aporta user i perms (permisos)
  • django.contrib.messages.context_processors.messages — aporta messages (missatges flash)
  • django.template.context_processors.debug — aporta debug (True/False) i sql_queries

Gràcies al processor auth, en qualsevol template pots usar directament {{ user.username }} o {% if user.is_authenticated %} sense haver de passar l'usuari explícitament des de la vista. Gràcies al processor messages, pots mostrar missatges flash amb {% for message in messages %}.

📌 Bones pràctiques

Organitza els context processors propis al fitxer nom_app/context_processors.py. Si l'aplicació creix, pots crear un fitxer per cada processador. Nomenals de forma descriptiva: prestecs_actius_lector és millor que dades_globals.

Python bibliapp/settings.py — registre del context processor 
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                # --- Built-in de Django (no eliminar) ---
                'django.template.context_processors.debug',
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',

                # --- Context processors propis de bibliapp ---
                'books.context_processors.prestecs_actius_lector',
                'books.context_processors.configuracio_biblioteca',
            ],
        },
    },
]

🔮 Avançat

Per a aplicacions grans on el context processor fa una consulta a la BD, pots usar el sistema de cache de Django per evitar consultes repetides: count = cache.get_or_set(f'prestecs_actius_{request.user.pk}', lambda: Prestec.objects.filter(...).count(), timeout=60). Amb un timeout d'1 minut el badge pot estar lleugerament desfasat, però la càrrega de la base de dades es redueix dràsticament.

# books/context_processors.py
from books.models import Llibre, Prestec

def resum_biblioteca(request):
    """Injecta estadístiques globals a tots els templates."""
    return {
        'llibres_disponibles': Llibre.objects.filter(disponible=True).count(),

        ),
    }

Context processor amb cache

Si un context processor fa una consulta costosa a la base de dades, s'executa en cada petició. La cache evita repetir la consulta innecessàriament.

Tasques:

  1. Modifica el context processor resum_biblioteca per cachejar el recompte de llibres_disponibles durant 60 segons.
  2. Usa cache.get_or_set('clau', callable, timeout) per la implementació.
  3. Afegeix una tercera clau: prestecs_vençuts_total (recompte global, també cachejat).
  4. Invalida la cache quan es crea o modifica un Llibre (usa signal).

PythonSolució completa
# books/context_processors.py
from django.core.cache import cache
from books.models import Llibre, Prestec

def resum_biblioteca(request):
    llibres_disponibles = cache.get_or_set(
        'biblio:llibres_disponibles',
        lambda: Llibre.objects.filter(disponible=True).count(),
        60
    )
    prestecs_vençuts = cache.get_or_set(
        'biblio:prestecs_vençuts',
        lambda: Prestec.objects.filter(estat='vençut').count(),
        60
    )
    meus_prestecs = 0
    if request.user.is_authenticated and hasattr(request.user, 'lector'):
        meus_prestecs = Prestec.objects.filter(lector=request.user.lector, estat='actiu').count()
    return {
        'llibres_disponibles': llibres_disponibles,
        'prestecs_vençuts_total': prestecs_vençuts,
        'meus_prestecs_actius': meus_prestecs,
    }

# books/signals.py
@receiver(post_save, sender=Llibre)
def invalidar_cache_biblioteca(sender, **kwargs):
    cache.delete('biblio:llibres_disponibles')
    cache.delete('biblio:prestecs_vençuts')
