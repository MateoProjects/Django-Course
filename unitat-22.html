Logging i Monitoratge

Configura el sistema de logging de Python i Django per registrar activitat, errors i esdeveniments de seguretat en fitxers rotatius separats.

En aquesta unitat aprendràs:

  • La jerarquia de loggers de Python i com Django la utilitza
  • Configurar el diccionari LOGGING: formatters, handlers i loggers
  • Usar StreamHandler per consola i RotatingFileHandler per fitxers
  • Entendre els cinc nivells de logging i quan usar cada un
  • Separar els logs de seguretat en un fitxer independent (com fa Medinet)
  • Bones pràctiques: logging.getLogger(__name__), no usar print()

◆ El sistema de logging de Python i Django

Python inclou un mòdul de logging estàndard (logging) extremadament potent. Django el configura i l'estén, però no el substitueix. El sistema funciona amb una jerarquia de loggers: cada logger té un nom (normalment el nom del mòdul, __name__), i els missatges pugen per la jerarquia fins que un handler els processa. Un logger anomenat bibliapp.views és fill de bibliapp, que al seu torn és fill del logger arrel (root).

La configuració es fa amb el diccionari LOGGING als settings. Té quatre seccions principals: version (sempre 1), formatters (com es presenta cada línia), handlers (on van els missatges) i loggers (quins loggers existeixen i amb quin nivell).

Nivells de logging

Nivell Valor numèric Quan usar-lo
DEBUG 10 Informació molt detallada per a diagnòstic en dev. Mai en producció.
INFO 20 Confirmació que les coses funcionen: creació d'objectes, inici de tasques.
WARNING 30 Situació inesperada que no trenca l'app però cal vigilar: intents de login fallits.
ERROR 40 Error que ha impedit completar una operació. Requereix atenció.
CRITICAL 50 Error crític que pot deixar el sistema inoperatiu. Alerta immediata.

Components del diccionari LOGGING

  • version: 1 — valor fix obligatori. Identifica la versió del schema de configuració.
  • disable_existing_loggers: False — crucial. Si és True, Django silenciaria els loggers de les biblioteques de tercers. Sempre posar False.
  • formatters — diccionari de formats. Cada formatter defineix com es veu una línia de log: data, nivell, nom del logger, missatge.
  • handlers — diccionari de handlers. Cada handler decideix on van els missatges: consola (StreamHandler), fitxer (FileHandler), email (AdminEmailHandler).
  • loggers — diccionari de loggers nomenats. Cada entrada especifica el nivell mínim i a quins handlers s'envia.
  • RotatingFileHandler — handler especial que crea un fitxer nou quan el fitxer actual supera maxBytes. Manté un màxim de backupCount fitxers antics.
⚠️ Mai usar print() en producció

El print() escriu a stdout sense cap context: no tens la data, no tens el nivell, no pots filtrar-lo ni enviar-lo a un fitxer. En producció, print() pot no aparèixer en cap lloc útil. Usa sempre logger.info(), logger.warning(), etc. La única excepció acceptable és el codi de scripts puntuals i management commands (on pots usar self.stdout.write()).

Python config/settings/base.py — configuració LOGGING completa 
# ─── config/settings/base.py ─────────────────────────────────
# Configuració de logging inspirada en MediNetNode.
# Dos fitxers separats: un per a l'app general, un per a seguretat.

import os
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent.parent

# Directori on es desaran els fitxers de log
LOG_DIR = BASE_DIR / 'logs'
LOG_DIR.mkdir(exist_ok=True)  # crea el directori si no existeix


LOGGING = {
    'version': 1,

    # No silenciar els loggers de biblioteques externes (Django, etc.)
    'disable_existing_loggers': False,

    # ── Formatters: com es veu cada línia al log ───────────────
    'formatters': {
        # Format estàndard per als fitxers
        'detallat': {
            'format': (
                '%(asctime)s | %(levelname)-8s | %(name)s | %(message)s'
            ),
            'datefmt': '%Y-%m-%d %H:%M:%S',
        },
        # Format compacte per a la consola durant el desenvolupament
        'consola': {
            'format': '%(levelname)s %(name)s: %(message)s',
        },
        # Format enriquit per als logs de seguretat
        'seguretat': {
            'format': (
                '%(asctime)s | SECURITY | %(levelname)-8s | '
                '%(name)s | %(message)s'
            ),
            'datefmt': '%Y-%m-%d %H:%M:%S',
        },
    },

    # ── Handlers: on van els missatges ────────────────────────
    'handlers': {
        # Consola: per a dev i per veure errors en temps real
        'consola': {
            'class': 'logging.StreamHandler',
            'formatter': 'consola',
            'level': 'DEBUG',
        },
        # Fitxer de l'aplicació amb rotació automàtica
        # maxBytes=5MB → crea fitxer nou; backupCount=5 → manté 5 còpies
        'fitxer_app': {
            'class': 'logging.handlers.RotatingFileHandler',
            'filename': LOG_DIR / 'bibliapp.log',
            'maxBytes': 5 * 1024 * 1024,  # 5 MB
            'backupCount': 5,
            'formatter': 'detallat',
            'level': 'INFO',
            'encoding': 'utf-8',
        },
        # Fitxer separat per a events de seguretat
        # Inspirat en l'arquitectura de MediNetNode
        'fitxer_seguretat': {
            'class': 'logging.handlers.RotatingFileHandler',
            'filename': LOG_DIR / 'security.log',
            'maxBytes': 10 * 1024 * 1024,  # 10 MB
            'backupCount': 10,
            'formatter': 'seguretat',
            'level': 'WARNING',
            'encoding': 'utf-8',
        },
    },

    # ── Loggers: quins loggers existeixen i on envien ─────────
    'loggers': {
        # Logger principal de bibliapp: INFO i superior → app + consola
        'bibliapp': {
            'handlers': ['consola', 'fitxer_app'],
            'level': 'INFO',
            'propagate': False,  # no enviar al logger arrel
        },
        # Logger de seguretat separat: WARNING i superior → fitxer seguretat
        'security': {
            'handlers': ['fitxer_seguretat'],
            'level': 'WARNING',
            'propagate': False,
        },
        # Logger de Django: només errors greus
        'django': {
            'handlers': ['consola', 'fitxer_app'],
            'level': 'ERROR',
            'propagate': False,
        },
        # Logger de peticions Django (accés HTTP)
        'django.request': {
            'handlers': ['fitxer_app'],
            'level': 'ERROR',
            'propagate': False,
        },
    },
}

◆ Loggers múltiples: per app, per mòdul i per seguretat

La convenció estàndard és obtenir un logger a cada mòdul Python usant logging.getLogger(__name__). La variable especial __name__ conté el nom complet del mòdul: en un fitxer cataleg/views.py dins d'un projecte bibliapp, __name__ val cataleg.views. Gràcies a la jerarquia, si configures el logger bibliapp als settings, tots els loggers dels submòduls (bibliapp.views, bibliapp.models) hereten la configuració automàticament.

  • logger = logging.getLogger(__name__) — obtenir el logger del mòdul actual. Ha de ser a nivell de mòdul (fora de funcions i classes).
  • logger.debug('missatge') — per a informació molt detallada que només vols en dev.
  • logger.info('Creat préstec %d', prestec.pk) — confirmació d'operació exitosa. Usa format %s/%d, no f-strings, per eficiència.
  • logger.warning('Intent login fallit per %s', username) — situació anòmala que no és un error però cal vigilar.
  • logger.error('Error en vista: %s', str(e)) — error que ha impedit completar l'operació.
  • logger.exception('Error inesperat') — com error() però afegeix automàticament el traceback complet. Usar sempre dins d'un bloc except.

Logger de seguretat separat

En aplicacions professionals (com Medinet), els esdeveniments de seguretat van a un fitxer separat. Això permet analitzar intents d'intrusió, bloqueigs de comptes i accessos no autoritzats de manera independent dels logs d'aplicació generals. El logger de seguretat s'usa explícitament en el codi: security_logger = logging.getLogger('security').

📌 propagate: False

Quan un logger té 'propagate': False, els seus missatges no pugen al logger pare. Si no poses aquest flag, un missatge processat per bibliapp podria aparèixer dues vegades: una al handler de bibliapp i una al handler del logger arrel. Posa sempre propagate: False als loggers que configures explícitament.

def llista_llibres(request):
    """Vista principal del catàleg."""
    llibres = Llibre.objects.select_related('autor').all()
    logger.debug('Consulta llista llibres: %d resultats', llibres.count())
    return render(request, 'cataleg/llista.html', {'llibres': llibres})


@login_required
def crear_prestec(request, pk):
    """Crea un préstec nou per a l'usuari autenticat."""
    llibre = get_object_or_404(Llibre, pk=pk)

    try:
        from prestecs.models import Prestec
        prestec = Prestec.objects.create(
            llibre=llibre,
            lector=request.user,
        )
        # Registrem la creació al log d'aplicació (INFO)
        logger.info(
            'Préstec creat — llibre: "%s" (id=%d), lector: %s',
            llibre.titol, llibre.pk, request.user.username
        )
        return redirect('prestecs:detall', pk=prestec.pk)

    except Exception as e:
        # logger.exception afegeix el traceback complet automàticament
        logger.exception(
            'Error inesperat creant préstec per llibre id=%d', pk
        )
        return render(request, 'error.html', {'missatge': str(e)}, status=500)


# ─── prestecs/middleware.py ───────────────────────────────────
import logging
from django.contrib.auth import get_user_model

# Els events de seguretat van al logger 'security' (fitxer separat)
security_logger = logging.getLogger('security')


class RegistreLoginMiddleware:
    """
    Middleware que registra intents de login fallits al log de seguretat.
    Inspirat en SessionTimeoutMiddleware de MediNetNode.
    """

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        response = self.get_response(request)

        # Detectar resposta 401/403 en rutes d'autenticació
        if (request.path.startswith('/auth/login') and
                response.status_code in (401, 403)):
            username = request.POST.get('username', 'desconegut')
            ip = request.META.get('REMOTE_ADDR', '?')
            security_logger.warning(
                'Intent de login fallit — usuari: %s, IP: %s',
                username, ip
            )

        return response


# ─── prestecs/signals.py ─────────────────────────────────────
import logging
from django.db.models.signals import post_save
from django.dispatch import receiver
from .models import Prestec

logger = logging.getLogger(__name__)


@receiver(post_save, sender=Prestec)
def notificar_prestec_creat(sender, instance, created, **kwargs):
    """
    Signal que s'activa cada cop que es crea o actualitza un Prestec.
    Registra la creació al log per traçabilitat.
    """
    if created:
        logger.info(
            'Signal post_save — nou Prestec id=%d, lector=%s, llibre="%s"',
            instance.pk,
            instance.lector.username,
            instance.llibre.titol,
        )
💡 Format dels missatges

Usa el format de substitució antic de Python (%s, %d) en lloc de f-strings als missatges de log. La raó és que el sistema de logging de Python és lazy: si el nivell del logger és superior al del missatge, la substitució no es fa mai, estalviant temps de CPU. Amb f-strings, la string es construeix sempre, fins i tot si el missatge no s'escriurà.

# biblioteca/logging_formatters.py
import json
import logging
from datetime import datetime, timezone

class JSONFormatter(logging.Formatter):
    def format(self, record):
        entrada = {
            'timestamp': datetime.fromtimestamp(
                record.created, tz=timezone.utc
            ).isoformat(),
            'level': record.levelname,
            'logger': record.name,
            'module': record.module,
            'line': record.lineno,
            'message': record.getMessage(),
        }

        if record.exc_info:
            entrada['exc_info'] = self.formatException(record.exc_info)

        if hasattr(record, 'user_id'):
            entrada['user_id'] = record.user_id

        if hasattr(record, 'request_id'):
            entrada['request_id'] = record.request_id

        return json.dumps(entrada, ensure_ascii=False)

◆ Resum de la unitat

Estructura LOGGING

  • version: 1
  • disable_existing_loggers: False
  • formatters: {...}
  • handlers: {...}
  • loggers: {...}

Handlers habituals

  • StreamHandler → consola
  • FileHandler → fitxer fix
  • RotatingFileHandler → rotació
  • AdminEmailHandler → email

Al codi

  • logging.getLogger(__name__)
  • logger.info / warning / error
  • logger.exception (amb traceback)
  • mai usar print() en producció

Bones pràctiques

  • propagate: False als loggers propis
  • logger separat per a security
  • format %s/%d, no f-strings
  • LOG_DIR.mkdir(exist_ok=True)
