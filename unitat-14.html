Middleware Personalitzat

Intercepta cada petició i resposta per afegir comportament transversal: logging, seguretat, timing i molt més.

En aquesta unitat aprendràs:

  • Entendre el cicle request/response i el paper dels middlewares a la pila de Django
  • Crear middleware modern amb __init__(get_response) i __call__(request)
  • Gestionar errors amb process_exception() i usar MiddlewareMixin
  • Implementar headers de seguretat, timeout de sessió i logging de temps de resposta

◆ El cicle request/response i l'estructura del middleware

Cada vegada que arriba una petició HTTP a Django, passa per una pila de middlewares de dalt a baix en la fase de request, i de baix a dalt en la fase de response. Pensa-ho com les capes d'una ceba: la petició va cap al centre (la vista) i la resposta torna cap a fora.

Navegador / Client HTTP

Un middleware modern de Django és simplement una classe callable. El mètode __init__ rep get_response (la funció que representa la resta de la pila: el següent middleware o la vista) i el guarda. El mètode __call__ rep la request, fa el que cal abans de cridar get_response(request), obté la resposta, fa el que cal després, i retorna la resposta.

  • __init__(self, get_response) — s'executa una sola vegada en arrencar el servidor. Aquí es fa la configuració inicial (llegir settings, compilar regex, etc.).
  • __call__(self, request) — s'executa per a cada petició. La lògica abans de get_response(request) és com un process_request; la lògica després és com un process_response.
  • process_exception(self, request, exception) — mètode opcional, s'executa si la vista llança una excepció. Si retorna una HttpResponse, atura la propagació de l'error.
  • MIDDLEWARE setting — llista ordenada de strings (camí complet) que defineix l'ordre d'execució. L'ordre importa molt: SessionMiddleware ha d'anar abans de qualsevol middleware que usi sessions.
⚠️ Ordre dels middlewares

A settings.py, l'ordre de la llista MIDDLEWARE determina l'ordre d'execució. Un middleware que depèn de la sessió (request.session) ha d'anar després de django.contrib.sessions.middleware.SessionMiddleware. Afegir els teus middlewares al final de la llista normalment és la posició més segura.

Python middleware.py — TimingMiddleware 
import time
import logging

logger = logging.getLogger(__name__)


class TimingMiddleware:
    """
    Mesura el temps de processament de cada petició i el registra al log.
    Útil per detectar vistes lentes sense necessitat d'eines externes.
    """

    def __init__(self, get_response):
        # get_response és la resta de la pila (vista o següent middleware)
        self.get_response = get_response
        # __init__ s'executa una sola vegada en arrencar Django

    def __call__(self, request):
        # --- Fase PRE-VISTA (equivalent a process_request) ---
        inici = time.monotonic()  # rellotge monotònic, immune a canvis d'hora del sistema

        # Cridem la vista (o el següent middleware)
        response = self.get_response(request)

        # --- Fase POST-VISTA (equivalent a process_response) ---
        durada_ms = (time.monotonic() - inici) * 1000

        # Afegim el temps com a header perquè el frontend el pugui llegir
        response['X-Response-Time'] = f"{durada_ms:.1f}ms"

        # Registrem al log si la petició tarda més de 500 ms
        if durada_ms > 500:
            logger.warning(
                "Petició lenta: %s %s → %d ms",
                request.method,
                request.path,
                durada_ms,
            )
        else:
            logger.debug(
                "%s %s → %.1f ms",
                request.method,
                request.path,
                durada_ms,
            )

        return response

    def process_exception(self, request, exception):
        """
        Si la vista llança una excepció, la registrem amb context.
        Retornar None deixa que Django gestioni l'error normalment.
        """
        logger.error(
            "Excepció a %s %s: %s",
            request.method,
            request.path,
            str(exception),
            exc_info=True,  # inclou el traceback complet al log
        )
        return None  # deixem que Django mostri la pàgina d'error habitual

◆ Casos d'ús reals: headers de seguretat i timeout de sessió

El middleware és el lloc ideal per a tot el comportament transversal: funcionalitat que ha d'aplicar-se a totes (o quasi totes) les peticions independentment de la vista concreta. A MediNetNode, per exemple, hi ha un SecurityHeadersMiddleware que afegeix headers HTTP de seguretat a totes les respostes, i un SessionTimeoutMiddleware que tanca la sessió automàticament si l'usuari porta molt de temps inactiu.

Per a casos on necessites separar clarament process_request i process_response en mètodes independents (en lloc del patró __call__), pots heretar de MiddlewareMixin. Això és útil quan portes codi de versions antigues de Django o quan la separació en mètodes millora la llegibilitat.

  • Content-Security-Policy — header que indica al navegador des de quins orígens pot carregar recursos. Prevé atacs XSS.
  • X-Content-Type-Options: nosniff — evita que el navegador "endevini" el tipus de contingut d'una resposta, prevenint atacs de MIME sniffing.
  • X-Frame-Options: DENY — impedeix que la pàgina es mostri en un <iframe>, prevenint clickjacking.
  • Strict-Transport-Security — força HTTPS per a totes les peticions futures durant un període determinat (HSTS).
  • SESSION_IDLE_TIMEOUT — camp de settings personalitzat per definir quants segons pot estar inactiva una sessió abans de tancar-la.
  • MiddlewareMixin — classe de compatibilitat de django.utils.deprecation que permet escriure process_request() i process_response() com a mètodes separats.
📌 Registrar el middleware

Un cop creada la classe, cal afegir el camí complet a la llista MIDDLEWARE a settings.py. Per exemple: 'bibliapp.middleware.TimingMiddleware'. Si el middleware accedeix a request.user, ha d'anar després de AuthenticationMiddleware.

Python middleware.py — SecurityHeadersMiddleware (inspirat en MediNetNode) 
import time
from django.conf import settings
from django.shortcuts import redirect
from django.utils.deprecation import MiddlewareMixin


class SecurityHeadersMiddleware:
    """
    Afegeix headers de seguretat HTTP a totes les respostes.
    Ha d'anar al principi de la llista MIDDLEWARE per cobrir totes les respostes,
    incloent les d'error (404, 500, etc.).
    """

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        response = self.get_response(request)

        # Evita que el navegador "endevini" el tipus MIME
        response['X-Content-Type-Options'] = 'nosniff'

        # Impedeix mostrar la pàgina en un iframe (protecció clickjacking)
        response['X-Frame-Options'] = 'DENY'

        # Activa el filtre XSS del navegador (llegat, però útil per compatibilitat)
        response['X-XSS-Protection'] = '1; mode=block'

        # Referrer policy: no enviar URL completa a tercers
        response['Referrer-Policy'] = 'strict-origin-when-cross-origin'

        # Content Security Policy: només recursos del mateix origen
        # En producció, restringeix encara més cada directiva
        csp = (
            "default-src 'self'; "
            "script-src 'self' https://cdnjs.cloudflare.com; "
            "style-src 'self' https://fonts.googleapis.com 'unsafe-inline'; "
            "font-src 'self' https://fonts.gstatic.com; "
            "img-src 'self' data:; "
            "frame-ancestors 'none';"
        )
        response['Content-Security-Policy'] = csp

        # HSTS: força HTTPS durant 1 any (només en producció)
        if not settings.DEBUG:
            response['Strict-Transport-Security'] = 'max-age=31536000; includeSubDomains'

        return response


class SessionTimeoutMiddleware(MiddlewareMixin):
    """
    Tanca la sessió automàticament si l'usuari porta massa temps inactiu.
    Usa MiddlewareMixin per poder separar process_request i process_response.
    """

    # Temps màxim d'inactivitat en segons (llegit des de settings)
    TIMEOUT = getattr(settings, 'SESSION_IDLE_TIMEOUT', 7200)  # 2 hores per defecte

    def process_request(self, request):
        """S'executa ABANS que arribi a la vista."""
        if not request.user.is_authenticated:
            return  # no fem res per a usuaris no autenticats

        ultima_activitat = request.session.get('ultima_activitat')
        ara = time.time()

        if ultima_activitat and (ara - ultima_activitat) > self.TIMEOUT:
            # La sessió ha caducat per inactivitat
            from django.contrib.auth import logout
            logout(request)
            # Guardem un missatge perquè la pàgina de login l'expliqui
            request.session['sessio_caducada'] = True
            return redirect(settings.LOGIN_URL)

        # Actualitzem l'hora de l'última activitat
        request.session['ultima_activitat'] = ara

    def process_response(self, request, response):
        """S'executa DESPRÉS que la vista hagi generat la resposta."""
        # Podríem afegir headers de timing aquí si combinéssim amb TimingMiddleware
        return response

🔮 Rate Limiting

Un altre cas d'ús clàssic del middleware és el rate limiting: limitar el nombre de peticions per IP o per usuari en un interval de temps. A MediNetNode hi ha un RateLimitMiddleware que compta les peticions en memòria (o Redis) i retorna un HttpResponse(status=429) quan se supera el límit. Alternativament, la biblioteca django-ratelimit ofereix el decorador @ratelimit per a vistes individuals.

# bibliapp/middleware.py
import time
import logging

logger = logging.getLogger('bibliapp.requests')

class RequestLogMiddleware:
    """Registra IP, mètode, path, codi de resposta i temps de cada petició."""

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        start = time.time()
        response = self.get_response(request)
        duration_ms = int((time.time() - start) * 1000)

        ip = request.META.get('HTTP_X_FORWARDED_FOR', request.META.get('REMOTE_ADDR', '?'))
        user = request.user.username if request.user.is_authenticated else 'anònim'

        logger.info(
            f"{request.method} {request.path} | "
            f"status={response.status_code} | "
            f"time={duration_ms}ms | "
            f"ip={ip} | user={user}"
        )
        return response

from django.conf import settings
from django.http import HttpResponse

class MaintenanceMiddleware:
    ALLOWED_PATHS = ['/admin/', '/static/']

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        en_manteniment = getattr(settings, 'MAINTENANCE_MODE', False)
        if en_manteniment:
            if any(request.path.startswith(p) for p in self.ALLOWED_PATHS):
                return self.get_response(request)
            if request.user.is_authenticated and request.user.is_superuser:
                return self.get_response(request)
            return HttpResponse(
                "<h1>🔧 Manteniment</h1><p>L'aplicació és en manteniment. Torna aviat.</p>",
                status=503,
                content_type='text/html; charset=utf-8'
            )
        return self.get_response(request)
