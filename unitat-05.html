Unitat 05 · Curs de Django

Migracions

Com Django gestiona l'evolució de l'esquema de base de dades de manera segura i versionada.

En aquesta unitat aprendràs:

  • Entendre el cicle makemigrations → migrate i els fitxers generats
  • Inspeccionar i gestionar l'historial de migracions amb showmigrations
  • Crear data migrations amb RunPython per poblar dades inicials
  • Revertir migracions i usar --fake per sincronitzar bases de dades existents

◆ Què és una migració i com funciona el cicle

Una migració és un fitxer Python que descriu un canvi en l'esquema de la base de dades: crear una taula, afegir un camp, modificar un índex... Django genera aquests fitxers automàticament comparant l'estat actual dels models amb l'historial de migracions ja aplicades.

El cicle habitual és sempre el mateix: primer generes la migració (Django escriu el fitxer), després l'apliques (Django executa l'SQL a la base de dades). Mai has d'escriure SQL a mà per als canvis d'esquema.

  • python manage.py makemigrations — detecta canvis als models i genera el fitxer de migració a app/migrations/
  • python manage.py migrate — aplica totes les migracions pendents a la base de dades
  • python manage.py showmigrations — mostra l'estat de totes les migracions ([X] aplicada, [ ] pendent)
  • python manage.py migrate app 0003 — aplica o reverteix fins a una migració específica
  • python manage.py squashmigrations app 0001 0005 — combina un rang de migracions en una de sola per netejar l'historial
  • python manage.py migrate app zero — reverteix totes les migracions d'una app (perillós en producció)
⚠️ Advertència

Mai editïs manualment un fitxer de migració ja aplicat en producció. Si necessites corregir un error, crea una nova migració que reverteixi el canvi.

Cada fitxer de migració conté una llista dependencies que indica quines altres migracions han d'existir abans. Això permet que Django apliqui les migracions en l'ordre correcte fins i tot quan hi ha diverses apps amb interdependències.

📌 Nota

La taula django_migrations a la base de dades registra quines migracions s'han aplicat. Django consulta aquesta taula per saber quines falten.

Python books/migrations/0002_add_isbn_to_llibre.py 
# Migració generada automàticament per Django quan afegim
# el camp isbn al model Llibre.

from django.db import migrations, models


class Migration(migrations.Migration):

    # Aquesta migració depèn de la inicial — Django l'aplicarà
    # sempre en ordre, garantint la consistència de l'esquema.
    dependencies = [
        ('books', '0001_initial'),
    ]

    operations = [
        migrations.AddField(
            model_name='llibre',
            name='isbn',
            # null=True permet que els llibres ja existents no
            # trenquin la migració: la columna nova arriba buida.
            field=models.CharField(
                max_length=13,
                blank=True,
                null=True,
                verbose_name='ISBN',
                help_text='Codi ISBN-13 del llibre',
            ),
        ),
        # Afegim un índex per agilitzar cerques per ISBN
        migrations.AddIndex(
            model_name='llibre',
            index=models.Index(fields=['isbn'], name='books_llibre_isbn_idx'),
        ),
    ]

◆ Data migrations: modificar dades, no només esquema

De vegades no n'hi ha prou d'afegir una columna: també cal poblar-la amb dades existents o inicials. Per a això existeixen les data migrations, que usen RunPython per executar codi Python arbitrari dins del context de la migració.

  • migrations.RunPython(func, reverse_func) — executa func(apps, schema_editor) en aplicar i reverse_func en revertir
  • apps.get_model('app', 'Model') — obté la versió histórica del model (no el model actual), imprescindible dins de RunPython
  • migrations.RunPython.noop — funció buida predefinida per quan la reversió no cal fer res
  • --fake — marca una migració com a aplicada sense executar-la; útil per sincronitzar una BD que ja té l'esquema correcte
  • --fake-initial — com --fake però només per a la migració inicial si les taules ja existeixen
🔮 Nota avançada

Dins de RunPython, usa sempre apps.get_model() en lloc d'importar el model directament. El model importat pot tenir camps nous que encara no existien quan la migració es va escriure, cosa que causaria errors difícils de depurar.

Les dependències entre migracions d'apps diferents es declaren explícitament. Per exemple, si la migració 0003 de loans afegeix una clau forana a books, cal declarar ('books', '0002_add_isbn_to_llibre') com a dependència. Django garanteix que books 0002 s'apliqui primer.

Python books/migrations/0003_isbn_data_migration.py 
# Data migration: pobla el camp isbn amb valors de prova
# per als llibres que ja existien a la base de dades.

from django.db import migrations


def poblar_isbn(apps, schema_editor):
    """Assigna ISBNs de prova als llibres que no en tenen."""
    # Obtenim la versió histórica del model —  és essencial
    # per evitar conflictes amb canvis posteriors al model real.
    Llibre = apps.get_model('books', 'Llibre')

    # Iterem tots els llibres sense ISBN i n'assignem un
    # basat en l'id per garantir unicitat en dades de prova.
    llibres_sense_isbn = Llibre.objects.filter(isbn__isnull=True)
    for llibre in llibres_sense_isbn:
        # Format ISBN-13 fictici basat en l'id del llibre
        llibre.isbn = f'978000000{str(llibre.id).zfill(4)}'
        llibre.save(update_fields=['isbn'])


def buidar_isbn(apps, schema_editor):
    """Reverteix: buida tots els ISBNs (torna al estat anterior)."""
    Llibre = apps.get_model('books', 'Llibre')
    Llibre.objects.all().update(isbn=None)


class Migration(migrations.Migration):

    dependencies = [
        # Primer cal que el camp isbn existeixi a l'esquema
        ('books', '0002_add_isbn_to_llibre'),
    ]

    operations = [
        migrations.RunPython(
            poblar_isbn,
            reverse_code=buidar_isbn,   # s'executa en fer migrate app 0002
        ),
    ]
📌 Comandes útils de diagnòstic

python manage.py showmigrations --list mostra tot l'historial. python manage.py sqlmigrate books 0002 mostra l'SQL que s'executarà sense aplicar-lo. Molt útil per revisar migracions en producció abans d'aplicar-les.

Python Solució completa 
# Pas 1: Afegir el camp al model
# books/models.py — afegir a Llibre:
isbn = models.CharField(max_length=17, unique=True, blank=True, default='')

# Pas 2: Crear la migració estructural
# python manage.py makemigrations books --name="add_isbn_to_llibre"
# Fitxer generat: books/migrations/0002_add_isbn_to_llibre.py
from django.db import migrations, models

class Migration(migrations.Migration):
    dependencies = [('books', '0001_initial')]
    operations = [
        migrations.AddField(
            model_name='llibre',
            name='isbn',
            field=models.CharField(blank=True, default='', max_length=17, unique=True),
        ),
    ]

# Pas 3: Data migration per omplir ISBNs de prova
# python manage.py makemigrations books --empty --name="populate_isbn"
# books/migrations/0003_populate_isbn.py
from django.db import migrations

def generar_isbn(apps, schema_editor):
    Llibre = apps.get_model('books', 'Llibre')
    for i, llibre in enumerate(Llibre.objects.filter(isbn=''), start=1):
        codi = f"978-84-{i:05d}-00-{i % 10}"
        llibre.isbn = codi
        llibre.save()

def revertir_isbn(apps, schema_editor):
    Llibre = apps.get_model('books', 'Llibre')
    Llibre.objects.all().update(isbn='')

class Migration(migrations.Migration):
    dependencies = [('books', '0002_add_isbn_to_llibre')]
    operations = [
        migrations.RunPython(generar_isbn, revertir_isbn),
    ]

# Pas 4: Aplicar
# python manage.py migrate
# python manage.py showmigrations books  # verificar [X] en totes

Squashmigrations i migració de renomenat

Quan un projecte acumula moltes migracions, es poden compactar en una sola per millorar el rendiment i la llegibilitat de l'historial. A més, renomenar un camp requereix una migració especial que preserva les dades existents sense perdre cap registre.

Tasques:

  1. Renomena el camp resum del model Llibre a descripcio fent servir RenameField en una migració manual
  2. Aplica la migració i verifica que les dades existents es conserven
  3. Compacta les migracions 0001 a 0003 en una sola amb squashmigrations
Python Codi inicial — books/migrations/0004_rename_resum_to_descripcio.py 
# books/migrations/0004_rename_resum_to_descripcio.py
from django.db import migrations

class Migration(migrations.Migration):
    dependencies = [
        ('books', '0003_populate_isbn'),
    ]
    operations = [
        # TODO: RenameField de 'resum' a 'descripcio' al model 'llibre'
    ]
💡 migrations.RenameField(model_name='llibre', old_name='resum', new_name='descripcio') és l'operació correcta. No cal makemigrations: crea el fitxer manualment i aplica'l directament.

Resultat esperat:

python manage.py migrate aplica el canvi sense perdre dades. squashmigrations books 0003 crea 0001_squashed_0003_*.py i l'historial queda net.

👁 Veure solució
Python Solució completa 
# books/migrations/0004_rename_resum_to_descripcio.py
from django.db import migrations

class Migration(migrations.Migration):
    dependencies = [
        ('books', '0003_populate_isbn'),
    ]
    operations = [
        migrations.RenameField(
            model_name='llibre',
            old_name='resum',
            new_name='descripcio',
        ),
    ]

# Aplicar:
# python manage.py migrate books 0004

# Compactar (squash) migracions 0001-0003:
# python manage.py squashmigrations books 0001 0003
# Això genera: books/migrations/0001_squashed_0003_populate_isbn.py
# Marcar com a aplicada:
# python manage.py migrate --fake books 0001_squashed_0003_populate_isbn

# Verificar:
# python manage.py showmigrations books

◆ Resum de la unitat

Comandes clau

  • makemigrations — genera fitxer

  • showmigrations — estat actual
  • sqlmigrate — previsualitza SQL
  • squashmigrations — compacta historial
  • migrate app zero — reverteix tot

Conceptes essencials

  • dependencies — ordre d'aplicació
  • RunPython — lògica Python en migracio
  • apps.get_model() — model históric
  • --fake — marcar sense executar
  • django_migrations — taula de registre
  • reverse_code — funció de reversió
