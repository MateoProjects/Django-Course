◆ Què és Django i per què existeix

Django és un framework web d'alt nivell escrit en Python que fomenta el desenvolupament ràpid i el disseny net i pragmàtic. Va néixer el 2003 a la redacció del diari Lawrence Journal-World per a gestionar continguts de notícies amb agilitat. Des de llavors s'ha convertit en un dels frameworks web més populars del món, usat per empreses com Instagram, Pinterest, Disqus i Mozilla.

El lema oficial és "The web framework for perfectionists with deadlines": Django inclou de sèrie tot el que una aplicació web real necessita: ORM, sistema d'autenticació, panell d'administració, sistema de formularis, gestió d'arxius estàtics i molt més. Això contrasta amb microframeworks com Flask, que requereixen afegir cada peça per separat.

  • Django 4.2 LTS — versió de suport a llarg termini, recomanada per a producció fins al 2026
  • batteries included — tot inclòs: ORM, admin, auth, formularis, cache, signals
  • DRY — Don't Repeat Yourself: principi fonamental del disseny de Django
  • python manage.py — eina de gestió principal per a totes les operacions de Django
📌 Prerequisit

Necessites Python 3.10 o superior. Comprova-ho amb python --version al terminal. Es recomana crear sempre un entorn virtual per a cada projecte: python -m venv .venv.

◆ El patró MVT — Model, Vista, Template

Django segueix el patró arquitectònic MVT, una variant del conegut MVC (Model-Vista-Controlador). La diferència principal és terminològica i de responsabilitats: el que en MVC seria el Controlador és la Vista en Django, i el que seria la Vista és el Template. Django gestiona la capa de controlador internament a través del sistema d'URLs.

  • Model — defineix l'estructura de les dades i la lògica de negoci; Django el mapa a la base de dades via l'ORM
  • Vista — rep la petició HTTP, consulta els models, prepara el context i retorna una resposta (normalment renderitzant un template)
  • Template — fitxer HTML amb el sistema de plantilles de Django; rep el context de la vista i genera el HTML final
  • URL dispatcher — el component que Django gestiona automàticament i que connecta URLs amb vistes (el "Controlador" de MVC)

El cicle d'una petició HTTP en Django segueix sempre el mateix flux: el navegador fa una petició → Django cerca la URL a urls.py → executa la Vista corresponent → la Vista consulta els Models → renderitza el Template → retorna la resposta HTTP.

🔮 Nota avançada

Django també suporta vistes que no renderitzen templates sinó que retornen JSON (JsonResponse), ideal per a APIs. Ho veurem a la unitat 17 amb Django REST Framework.

◆ Estructura d'un projecte Django

Quan crees un projecte amb django-admin startproject nom, Django genera una estructura de fitxers estàndard. Entendre quin fitxer fa què és imprescindible per a treballar amb comoditat des del primer dia.

  • manage.py — script de gestió del projecte; l'ús directe és equivalent a django-admin però amb les settings carregades automàticament
  • settings.py — configuració global: base de dades, apps instal·lades, middleware, templates, arxius estàtics, etc.
  • urls.py — taula d'enrutament principal; connecta patrons d'URL amb vistes o inclou urls.py d'apps
  • wsgi.py — punt d'entrada per a servidors WSGI (Gunicorn, uWSGI) en producció
  • asgi.py — punt d'entrada per a servidors ASGI (Daphne, Uvicorn) per a suport de WebSockets
  • models.py — dins de cada app: definició dels models de dades
  • views.py — dins de cada app: lògica de les vistes
  • admin.py — dins de cada app: registre de models al panell d'administració
  • apps.py — configuració de l'app (nom, etiqueta, senyal de preparació)
  • migrations/ — carpeta que conté les migracions de la base de dades generades automàticament
Shell terminal — crear projecte i app 
# Instal·lar Django en un entorn virtual nou
python -m venv .venv
source .venv/bin/activate      # Linux/macOS
# .venv\Scripts\activate       # Windows

pip install django==4.2.*

# Verificar la instal·lació
python -m django --version

# Crear el projecte (genera la carpeta bibliapp_project/)
django-admin startproject bibliapp_project .
# El punt final posa els fitxers a l'arrel, no en una subcarpeta extra

# Estructura generada:
# manage.py
# bibliapp_project/
#   __init__.py
#   settings.py
#   urls.py
#   asgi.py
#   wsgi.py

# Crear l'app books (una app és un mòdul reutilitzable)
python manage.py startapp books

# Estructura de l'app generada:
# books/
#   __init__.py
#   admin.py
#   apps.py
#   models.py
#   tests.py
#   views.py
#   migrations/
#     __init__.py

# Arrancar el servidor de desenvolupament (port 8000 per defecte)
python manage.py runserver

# O en un port específic:
python manage.py runserver 0.0.0.0:5000
⚠️ Important

Quan crees una app nova, has d'afegir-la a INSTALLED_APPS al fitxer settings.py perquè Django la reconegui. Sense aquest pas, les migracions de l'app no s'aplicaran i els templates no es trobaran.

Python books/views.py 
from django.http import HttpResponse
from django.shortcuts import render


def inici(request):
    """Vista principal de l'app books.

    Rep un objecte HttpRequest i retorna un HttpResponse.
    Tota vista Django segueix exactament aquest contracte.
    """
    # La variable 'request' conté tota la informació de la petició:
    # request.method (GET, POST, PUT...)
    # request.user (usuari autenticat o AnonymousUser)
    # request.GET / request.POST (dades del formulari o query string)
    return HttpResponse("Hola, biblioteca! Benvingut a bibliapp.")


def llista_llibres(request):
    """Vista que usa un template per renderitzar la resposta.

    El context és un diccionari que el template rebrà com a variables.
    """
    # En unitats posteriors obtindrem això de la base de dades
    context = {
        'titol': 'Catàleg de Llibres',
        'llibres': [
            {'titol': 'El Quixot', 'autor': 'Cervantes'},
            {'titol': 'Tirant lo Blanc', 'autor': 'Joanot Martorell'},
            {'titol': 'La Plaça del Diamant', 'autor': 'Mercè Rodoreda'},
        ],
    }
    # render() combina un template amb el context i retorna HttpResponse
    return render(request, 'books/llista.html', context)
Python books/urls.py — crear aquest fitxer nou 
from django.urls import path
from . import views

# app_name permet usar namespaces: {% url 'books:inici' %}
app_name = 'books'

urlpatterns = [
    # /books/           → vista inici
    path('', views.inici, name='inici'),
    # /books/llibres/   → vista llista_llibres
    path('llibres/', views.llista_llibres, name='llista-llibres'),
]
Python bibliapp_project/urls.py — afegir l'include 
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    # Inclou totes les URLs de l'app books sota el prefix /books/
    path('books/', include('books.urls')),
]

Python Solució completa 
# books/views.py
from django.http import HttpResponse

def comptador_visites(request):
    visites = request.session.get('visites', 0)
    visites += 1
    request.session['visites'] = visites
    return HttpResponse(f"<h2>Has visitat aquesta pàgina {visites} vegada/es</h2>")

    path('visites/', views.comptador_visites, name='comptador_visites'),
]
