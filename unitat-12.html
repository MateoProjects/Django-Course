Unitat 12 · Curs de Django

Autenticació i Sessions

Gestiona usuaris, permisos, sessions i models d'autenticació personalitzats

En aquesta unitat aprendràs:

  • Crear un model d'usuari personalitzat amb AbstractUser i configurar AUTH_USER_MODEL
  • Usar login(), logout(), authenticate() i @login_required
  • Implementar vistes de registre, perfil i canvi de contrasenya
  • Crear un AUTHENTICATION_BACKEND personalitzat i validators de contrasenya

◆ El model User, AbstractUser i el cicle d'autenticació

Django inclou un sistema d'autenticació complet basat en el model User de django.contrib.auth. Per a la majoria de projectes reals, però, necessitem camps addicionals (telèfon, avatar, número de carnet de soci…) o un comportament diferent. La solució recomanada és crear un model propi que hereti d'AbstractUser i configurar AUTH_USER_MODEL a settings.py abans de la primera migració. Intentar canviar-ho més tard és molt complex.

Flux d'autenticació Django

1
Formulari envia credencials → username + password
│
2
authenticate(request, username=..., password=...) → User o None
│
3
login(request, user) → crea sessió al servidor
│
4
redirect() → l'usuari accedeix a les pàgines protegides
│
5
logout(request) → destrueix la sessió
  • AbstractUser — classe base que inclou username, password, email, first_name, last_name, is_staff, is_active, date_joined; la més senzilla d'ampliar
  • AbstractBaseUser — base mínima (només password i last_login); per a sistemes d'autenticació completament personalitzats
  • AUTH_USER_MODEL = 'users.CustomUser' — configuració a settings que indica a Django quin model usar com a User
  • get_user_model() — funció per referenciar el model d'usuari actiu sense acoblar-se a la classe concreta
  • authenticate(request, username, password) — comprova les credencials contra tots els backends; retorna l'objecte User si és correcte o None
  • login(request, user) — inicia la sessió guardant l'ID de l'usuari a request.session
  • logout(request) — neteja tota la informació de sessió de l'usuari actual
  • @login_required — decorador que redirigeix a settings.LOGIN_URL si l'usuari no està autenticat
  • update_session_auth_hash(request, user) — crida obligatòria en canviar la contrasenya per evitar que la sessió quedi invalidada
  • request.session — diccionari persistent que es desa al servidor (o cache/BD) entre peticions
⚠️ Crític

Defineix AUTH_USER_MODEL i crea el model personalitzat abans de fer la primera migració del projecte. Canviar-ho després requereix manipulació manual de migracions i pot trencar relacions de clau forana en tot el projecte.

Python users/models.py — CustomUser + settings 
# users/models.py
from django.contrib.auth.models import AbstractUser
from django.db import models


class CustomUser(AbstractUser):
    """
    Model d'usuari personalitzat per a bibliapp.
    Heretem AbstractUser per mantenir tota la lògica d'autenticació
    built-in (grups, permisos, is_staff, is_active, etc.) i afegim
    els camps específics de la biblioteca.
    """
    numero_carnet = models.CharField(
        max_length=20,
        unique=True,
        blank=True,
        null=True,
        verbose_name='Número de carnet',
        help_text='Identificador únic del carnet de biblioteca.',
    )
    data_alta = models.DateField(
        auto_now_add=True,
        verbose_name='Data d\'alta',
    )
    telefon = models.CharField(
        max_length=15,
        blank=True,
        verbose_name='Telèfon de contacte',
    )

    class Meta:
        verbose_name = 'Usuari'
        verbose_name_plural = 'Usuaris'

    def __str__(self):
        return f"{self.get_full_name()} ({self.username})"

    def prestecs_actius(self):
        """Mètode d'utilitat: retorna els préstecs actius d'aquest usuari."""
        # Evitem importació circular posant-la aquí dins
        from books.models import Prestec
        return Prestec.objects.filter(lector__usuari=self, retornat=False)
Python users/views.py — registre, login, logout, perfil 
from django.shortcuts import render, redirect
from django.contrib.auth import login, logout, authenticate, update_session_auth_hash
from django.contrib.auth.decorators import login_required
from django.contrib import messages
from django.contrib.auth.forms import PasswordChangeForm
from users.forms import RegistreForm, PerfilForm


def vista_registre(request):
    """Registre d'un nou usuari. Després del registre fa login automàtic."""
    if request.user.is_authenticated:
        return redirect('books:llista')  # ja autenticat, no cal registrar-se

    if request.method == 'POST':
        form = RegistreForm(request.POST)
        if form.is_valid():
            usuari = form.save()
            # Fem login automàtic just després del registre
            login(request, usuari)
            messages.success(request, f"Benvingut/da, {usuari.first_name}! El compte s'ha creat correctament.")
            return redirect('books:llista')
    else:
        form = RegistreForm()

    return render(request, 'users/registre.html', {'form': form})


def vista_login(request):
    """Login manual. Django també ofereix LoginView built-in."""
    if request.user.is_authenticated:
        return redirect('books:llista')

    if request.method == 'POST':
        username = request.POST.get('username', '').strip()
        password = request.POST.get('password', '')

        # authenticate() prova tots els AUTHENTICATION_BACKENDS de settings
        usuari = authenticate(request, username=username, password=password)

        if usuari is not None:
            login(request, usuari)
            # next: redirigeix a on l'usuari volia anar (si ve de @login_required)
            next_url = request.GET.get('next', 'books:llista')
            return redirect(next_url)
        else:
            messages.error(request, "Nom d'usuari o contrasenya incorrectes.")

    return render(request, 'users/login.html')


def vista_logout(request):
    """Logout: destrueix la sessió i redirigeix a l'inici."""
    logout(request)
    messages.info(request, "Has tancat la sessió correctament.")
    return redirect('books:llista')


@login_required
def vista_perfil(request):
    """Perfil de l'usuari: editar dades personals."""
    if request.method == 'POST':
        form = PerfilForm(request.POST, instance=request.user)
        if form.is_valid():
            form.save()
            messages.success(request, "Perfil actualitzat correctament.")
            return redirect('users:perfil')
    else:
        form = PerfilForm(instance=request.user)

    return render(request, 'users/perfil.html', {'form': form})


@login_required
def canvi_contrasenya(request):
    """
    Canvi de contrasenya de l'usuari actual.
    update_session_auth_hash() és essencial: sense ell, Django invalidaria
    la sessió actual en canviar la contrasenya i desconnectaria l'usuari.
    """
    if request.method == 'POST':
        form = PasswordChangeForm(request.user, request.POST)
        if form.is_valid():
            usuari = form.save()
            # Manté la sessió activa amb la nova contrasenya
            update_session_auth_hash(request, usuari)
            messages.success(request, "Contrasenya canviada correctament.")
            return redirect('users:perfil')
    else:
        form = PasswordChangeForm(request.user)

    return render(request, 'users/canvi_contrasenya.html', {'form': form})

◆ Backends d'autenticació, sessions i validators de contrasenya

Per defecte, Django autentica els usuaris per username i password. Si volem permetre login per email (molt habitual en aplicacions reals), hem de crear un Authentication Backend personalitzat: una classe amb els mètodes authenticate() i get_user(), que registrem a AUTHENTICATION_BACKENDS de settings. Django provarà tots els backends en ordre fins que un d'ells autentiqui l'usuari.

Les sessions permeten mantenir estat entre peticions HTTP (que per naturalesa són sense estat). request.session funciona com un diccionari Python: el que hi guardes persisteix entre peticions del mateix usuari fins que la sessió expira o es destrueix amb logout(). El backend de sessió per defecte és DatabaseSession (guarda les dades a la BD), però es pot configurar amb Redis per a millor rendiment.

  • AUTHENTICATION_BACKENDS — llista de strings amb els backends actius a settings
  • authenticate() del backend — rep request i qualsevol kwarg; retorna User o None
  • get_user(user_id) del backend — recupera l'usuari per ID de sessió; necessari per a totes les peticions autenticades
  • request.session['clau'] = valor — desa dades a la sessió
  • request.session.get('clau', default) — llegeix dades de la sessió de forma segura
  • del request.session['clau'] — elimina una clau de la sessió
  • SESSION_COOKIE_AGE — durada de la sessió en segons (per defecte 1209600 = 2 setmanes)
  • AUTH_PASSWORD_VALIDATORS — llista de validators de contrasenya a settings
📌 Sessions

Executa python manage.py clearsessions periòdicament per eliminar les sessions caducades de la base de dades. En producció, configura una tasca programada (cron o Celery) per fer-ho automàticament. Les sessions expirades consumeixen espai però no afecten la seguretat.

Python users/backends.py — login per email 
from django.contrib.auth import get_user_model
from django.contrib.auth.backends import ModelBackend

User = get_user_model()


class EmailBackend(ModelBackend):
    """
    Backend d'autenticació que permet login per adreça de correu.
    Heretem de ModelBackend per mantenir la lògica de permisos built-in
    (has_perm, has_module_perms, etc.) i només sobreescrivim authenticate().
    """

    def authenticate(self, request, username=None, password=None, **kwargs):
        """
        Intenta autenticar buscant per email (username pot ser email).
        Si troba l'usuari, comprova la contrasenya. Si no la supera,
        retorna None (Django provarà el backend següent).
        """
        if username is None:
            return None

        try:
            # Cerca per email case-insensitive (iexact)
            usuari = User.objects.get(email__iexact=username)
        except User.DoesNotExist:
            # Fem un hash fals per evitar timing attacks:
            # si no fem res, un atacant pot mesurar si el mail existeix
            User().set_password(password)
            return None

        if usuari.check_password(password) and self.user_can_authenticate(usuari):
            return usuari
        return None

# users/validators.py
from django.core.exceptions import ValidationError


class ContrasenyaAmbNumeroValidator:
    """
    Validator personalitzat: la contrasenya ha de contenir almenys un dígit.
    Django crida validate() quan s'estableix o es canvia la contrasenya.
    """

    def validate(self, password, user=None):
        if not any(c.isdigit() for c in password):
            raise ValidationError(
                "La contrasenya ha de contenir almenys un número.",
                code='password_no_numero',
            )

    def get_help_text(self):
        """Text d'ajuda que Django mostra al formulari de canvi de contrasenya."""
        return "La contrasenya ha d'incloure almenys un número (0-9)."

from django import forms
from django.contrib.auth import get_user_model
from django.contrib.auth.forms import UserCreationForm

User = get_user_model()


class RegistreForm(UserCreationForm):
    """
    Formulari de registre que estén UserCreationForm per afegir
    els camps addicionals del nostre CustomUser.
    UserCreationForm ja gestiona la validació de la contrasenya
    (doble confirmació + AUTH_PASSWORD_VALIDATORS).
    """
    email = forms.EmailField(required=True, label='Adreça de correu')
    first_name = forms.CharField(max_length=50, required=True, label='Nom')
    last_name  = forms.CharField(max_length=50, required=True, label='Cognoms')

    class Meta(UserCreationForm.Meta):
        model = User
        fields = ('username', 'email', 'first_name', 'last_name', 'password1', 'password2')

    def clean_email(self):
        """Comprova que l'email no estigui ja registrat."""
        email = self.cleaned_data['email']
        if User.objects.filter(email__iexact=email).exists():
            raise forms.ValidationError("Ja existeix un compte amb aquesta adreça de correu.")
        return email.lower()  # guardem sempre en minúscules


class PerfilForm(forms.ModelForm):
    """Formulari per editar el perfil de l'usuari autenticat."""
    class Meta:
        model = User
        fields = ['first_name', 'last_name', 'email', 'telefon']
        labels = {
            'first_name': 'Nom',
            'last_name':  'Cognoms',
            'email':      'Adreça de correu',
            'telefon':    'Telèfon',
        }

# users/backends.py
from django.contrib.auth import get_user_model
from django.contrib.auth.backends import ModelBackend

User = get_user_model()

class EmailBackend(ModelBackend):
    def authenticate(self, request, username=None, password=None, **kwargs):
        try:
            user = User.objects.get(email=username)
        except User.DoesNotExist:
            return None
        if user.check_password(password) and self.user_can_authenticate(user):
            return user
        return None
