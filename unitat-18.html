◆ pytest-django: configuració i fixtures fonamentals

Django inclou el seu propi sistema de testing basat en unittest.TestCase, però pytest-django és la manera moderna i preferida. Ofereix fixtures componibles, markers declaratius, millors missatges d'error i integració nativa amb plugins de pytest com pytest-cov per a cobertura de codi.

Característica Django TestCase pytest-django
Sintaxi Classes que hereten de TestCase Funcions simples amb fixtures
Fixtures setUp / setUpClass Funcions reutilitzables amb scope configurable
Base de dades Transaction rollback automàtic @pytest.mark.django_db explícit
Paral·lelisme Limitat Compatible amb pytest-xdist
Assertions self.assertEqual() assert a == b nadiu Python

El fitxer conftest.py és el cor de la configuració de pytest. S'executa automàticament abans de qualsevol test i pot viure a qualsevol nivell del directori (les fixtures definides al conftest.py d'un directori pare estan disponibles als tests fills). La clau és el paràmetre scope de les fixtures:

  • scope='function' — la fixture s'executa de nou per a cada test (comportament per defecte); la BD es reinicia entre tests
  • scope='class' — compartida entre tots els tests d'una mateixa classe
  • scope='module' — compartida entre tots els tests d'un fitxer
  • scope='session' — s'executa UNA SOLA vegada per a tota la sessió de tests; ideal per a fixtures costoses com la creació de rols
  • django_db_setup — fixture especial de pytest-django per personalitzar la creació de la BD de test
  • django_db_blocker — objecte que permet bloquejar/desbloquejar l'accés a la BD en fixtures de sessió
⚠️ Atenció crítica

Les fixtures amb scope='session' comparteixen l'estat entre tests. Si un test modifica un objecte creat per una fixture de sessió, els tests posteriors veuran l'objecte modificat i fallaran de manera imprevisible. Per als rols i configuració global, usa scope='session'; per als usuaris de test, usa scope='function' perquè cada test tingui l'usuari net.

El marker @pytest.mark.django_db és obligatori a qualsevol test que accedeixi a la base de dades. Sense ell, pytest-django llança un error per protegir els tests d'accedir a la BD per accident. Hi ha una variant @pytest.mark.django_db(transaction=True) per a tests que necessiten testar senyals, transaccions i rollbacks reals.

  • db — fixture built-in que concedeix accés a la BD (equivalent a @pytest.mark.django_db)
  • client — fixture que retorna un django.test.Client per fer peticions HTTP
  • admin_client — client ja autenticat com a superusuari
  • rf — RequestFactory per crear peticions HTTP sense passar pel middleware
  • settings — fixture per modificar settings temporalment durant un test

◆ Tests de models, vistes i API REST

Un bon conjunt de tests segueix la piràmide de testing: molts tests unitaris (ràpids, aïllats), alguns tests d'integració (que toquen la BD o la xarxa interna) i pocs tests end-to-end. Amb pytest-django, els markers personalitzats permeten executar subconjunts: pytest -m unit executa només els tests unitaris, útil per al cicle de desenvolupament ràpid.

  • @pytest.mark.unit — test que no accedeix a la BD ni a serveis externs; no necessita @pytest.mark.django_db
  • @pytest.mark.integration — test que accedeix a la BD, l'API o serveis; necessita @pytest.mark.django_db
  • client.get('/url/') — petició GET; retorna un HttpResponse amb status_code i content
  • client.post('/url/', data, content_type='application/json') — petició POST amb cos JSON
  • client.force_login(user) — autentica l'usuari al client de test sense passar pel formulari de login
  • APIClient — client de DRF que gestiona automàticament les capçaleres JSON i l'autenticació per token
  • api_client.force_authenticate(user=user) — bypass d'autenticació per a tests d'API sense tokens reals
  • response.json() — deserialitza el cos JSON de la resposta; equivalent a response.data a DRF

Per als tests de models, l'objectiu és verificar que la lògica de negoci funciona correctament: que els camps es guarden bé, que les validacions salten quan toca, i que els signals i mètodes personalitzats fan allò que han de fer. Per als tests de vistes, l'objectiu és verificar el codi de resposta HTTP, que els templates s'usen correctament i que els redirects funcionen. Per als tests d'API, es comprova el codi HTTP, l'estructura del JSON de resposta i l'efecte sobre la BD.

# tests/test_models.py
"""
Tests unitaris i d'integració per als models de bibliapp.
"""
import pytest
from datetime import date, timedelta
from django.core.exceptions import ValidationError


@pytest.mark.integration
@pytest.mark.django_db
class TestPrestecModel:
    """Tests que verifiquen la lògica del model Prestec."""

    def test_crear_prestec_marca_llibre_com_no_disponible(self, llibre_disponible, usuari_lector):
        """
        Quan es crea un Prestec, el signal post_save ha de marcar
        el Llibre com a no disponible.
        """
        from biblioteca.models import Prestec

        assert llibre_disponible.disponible is True  # condició inicial

        Prestec.objects.create(
            llibre=llibre_disponible,
            lector=usuari_lector,
            data_inici=date.today(),
            data_fi_prevista=date.today() + timedelta(days=14),
            actiu=True,
        )

        # Recarreguem des de la BD per veure el valor actualitzat pel signal
        llibre_disponible.refresh_from_db()
        assert llibre_disponible.disponible is False

    def test_no_es_pot_prestar_un_llibre_no_disponible(self, prestec_actiu, usuari_admin):
        """
        No es pot crear un segon préstec sobre un llibre ja prestat.
        La validació hauria de llançar ValidationError.
        """
        from biblioteca.models import Prestec

        # El llibre ja no és disponible gràcies al prestec_actiu
        assert prestec_actiu.llibre.disponible is False

        amb_errors = Prestec(
            llibre=prestec_actiu.llibre,
            lector=usuari_admin,
            data_inici=date.today(),
            data_fi_prevista=date.today() + timedelta(days=7),
            actiu=True,
        )

        with pytest.raises(ValidationError, match="no disponible"):
            amb_errors.full_clean()  # activa les validadors del model

    def test_str_del_prestec_inclou_titol_i_lector(self, prestec_actiu):
        """El __str__ del Prestec ha d'incloure el títol i el nom del lector."""
        resultat = str(prestec_actiu)
        assert prestec_actiu.llibre.titol in resultat
        assert prestec_actiu.lector.username in resultat

@pytest.mark.integration
@pytest.mark.django_db
class TestVistesLlibre:
    """Tests de les vistes basades en funcions de bibliapp."""

    def test_llista_llibres_retorna_200_amb_usuari_autenticat(
        self, client_autenticat, llibre_disponible
    ):
        """La vista llista_llibres ha de retornar HTTP 200."""
        resposta = client_autenticat.get('/biblioteca/llibres/')
        assert resposta.status_code == 200

    def test_llista_llibres_redirigeix_usuari_no_autenticat(self, client):
        """Sense login, la vista ha de redirigir al formulari d'autenticació."""
        resposta = client.get('/biblioteca/llibres/')
        # 302 redirect cap a /accounts/login/?next=...
        assert resposta.status_code == 302
        assert '/accounts/login/' in resposta['Location']

    def test_llista_llibres_filtra_per_disponible(
        self, client_autenticat, llibre_disponible, autor
    ):
        """El filtre ?disponible=true retorna només els llibres disponibles."""
        from biblioteca.models import Llibre
        # Creem un segon llibre no disponible
        Llibre.objects.create(
            titol='Solitud',
            isbn='9788429716023',
            any_publicacio=1905,
            autor=autor,
            disponible=False,
        )

        resposta = client_autenticat.get('/biblioteca/llibres/?disponible=true')
        assert resposta.status_code == 200
        # Comprovem el context del template
        llibres = resposta.context['llibres']
        assert all(ll.disponible for ll in llibres)
        assert llibres.count() == 1  # només el llibre_disponible

"""

import pytest
from datetime import date, timedelta


@pytest.mark.integration
@pytest.mark.django_db
class TestAPILlibres:
    """Tests dels endpoints de Llibre a la API REST."""

    def test_llista_llibres_requereix_autenticacio(self, api_client):
        """GET /api/llibres/ sense autenticació ha de retornar 401."""
        resposta = api_client.get('/api/llibres/')
        assert resposta.status_code == 401

    def test_llista_llibres_retorna_200_amb_usuari_valid(
        self, api_client_autenticat, llibre_disponible
    ):
        """GET /api/llibres/ amb autenticació ha de retornar 200 i una llista."""
        resposta = api_client_autenticat.get('/api/llibres/')
        assert resposta.status_code == 200
        dades = resposta.json()
        assert isinstance(dades['results'], list)
        assert len(dades['results']) >= 1

    def test_filtre_disponible_funciona_a_la_api(
        self, api_client_autenticat, llibre_disponible, autor
    ):
        """GET /api/llibres/?disponible=false no retorna el llibre disponible."""
        from biblioteca.models import Llibre
        Llibre.objects.create(
            titol='Crim i Càstig',
            isbn='9788490060537',
            any_publicacio=1866,
            autor=autor,
            disponible=False,
        )

        resposta = api_client_autenticat.get('/api/llibres/?disponible=false')
        assert resposta.status_code == 200
        titols = [ll['titol'] for ll in resposta.json()['results']]
        assert 'Crim i Càstig' in titols
        assert 'La plaça del Diamant' not in titols

@pytest.mark.django_db
class TestAPIPrestecs:
    """Tests dels endpoints de Prestec a la API REST."""

    def test_crear_prestec_via_api(self, api_client_autenticat, llibre_disponible):
        """POST /api/prestecs/ ha de crear el préstec i retornar 201."""
        dades = {
            'llibre': llibre_disponible.id,
            'data_inici': str(date.today()),
            'data_fi_prevista': str(date.today() + timedelta(days=14)),
        }
        resposta = api_client_autenticat.post('/api/prestecs/', dades, format='json')
        assert resposta.status_code == 201
        # El lector s'ha d'assignar automàticament pel perform_create
        assert 'id' in resposta.json()

    def test_retornar_prestec_via_api(self, api_client_autenticat, prestec_actiu):
        """POST /api/prestecs/{id}/retornar/ ha de marcar el préstec com a retornat."""
        url = f'/api/prestecs/{prestec_actiu.id}/retornar/'
        resposta = api_client_autenticat.post(url)
        assert resposta.status_code == 200

        # Verifiquem la BD directament — la font de la veritat
        prestec_actiu.refresh_from_db()
        assert prestec_actiu.data_retorn == date.today()
        assert prestec_actiu.actiu is False

        prestec_actiu.llibre.refresh_from_db()
        assert prestec_actiu.llibre.disponible is True

# tests/test_views.py
import pytest
from django.urls import reverse

@pytest.mark.django_db
def test_llista_llibres_anonima(client):
    url = reverse('biblioteca:llista_llibres')
    resposta = client.get(url)
    assert resposta.status_code == 200

@pytest.mark.django_db
def test_detall_llibre(client, llibre):
    url = reverse('biblioteca:detall_llibre', kwargs={'pk': llibre.pk})
    resposta = client.get(url)
    assert resposta.status_code == 200
    assert 'Cent anys de solitud' in resposta.content.decode()

# tests/test_api.py
import pytest
from django.urls import reverse

@pytest.mark.django_db
def test_crear_llibre_sense_auth(client):
    url = reverse('api:llibre-list')
    dades = {
        'titol': 'Nou llibre',
        'any_publicacio': 2024,
        'disponible': True
    }
    resposta = client.post(url, dades, content_type='application/json')
    assert resposta.status_code in [401, 403]

@pytest.mark.django_db
def test_llistar_llibres_api(client, llibre):
    url = reverse('api:llibre-list')
    resposta = client.get(url)
    assert resposta.status_code == 200
    dades = resposta.json()
    assert len(dades) >= 1
