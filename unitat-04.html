L'ORM — QuerySets i Consultes

Consulta la base de dades amb Python pur: sense SQL, amb tot el poder.

En aquesta unitat aprendràs:

  • Usar el manager objects i els mètodes bàsics: all, filter, exclude, get
  • Aplicar lookups de camp: contains, gt, in, range, isnull i molts més
  • Encadenar QuerySets i entendre la seva avaluació lazy
  • Consultes avançades amb Q() per OR/AND i F() per comparar camps
  • Agregar i anotar: annotate(), aggregate()
  • Optimitzar amb select_related() i prefetch_related()

◆ El Manager i els mètodes bàsics

Cada model Django porta un Manager per defecte accessible com a NomModel.objects. El Manager és la porta d'entrada a totes les consultes: retorna QuerySets, que són objectes lazy (no executen cap SQL fins que realment es necessiten les dades). Això permet encadenar filtres, ordenacions i anotacions sense fer múltiples viatges a la base de dades.

1
Construcció del QuerySet
Llibre.objects.filter(estat='disponible').order_by('titol')
2
Avaluació lazy — el SQL no s'executa fins aquí
for ll in qs: / list(qs) / qs[0] / bool(qs)
3
Cache del QuerySet
Segona iteració usa la cache interna — sense nou SQL
  • Model.objects.all() — retorna tots els registres (QuerySet avaluat lazily)
  • .filter(**kwargs) — filtra per condicions; retorna un QuerySet nou (encadenable)
  • .exclude(**kwargs) — exclou els registres que compleixen la condició
  • .get(**kwargs) — retorna exactament un objecte; llança DoesNotExist o MultipleObjectsReturned
  • .first() / .last() — primer o últim registre; retorna None si el QuerySet és buit (mai llança excepció)
  • .count() — executa SELECT COUNT(*); molt eficient, no carrega objectes
  • .exists() — executa SELECT 1 LIMIT 1; el més eficient per comprovar existència
  • .order_by('camp') — ordena ascendent; '-camp' descendent; '?' aleatori
  • .values('c1', 'c2') — retorna diccionaris en lloc d'objectes (millor rendiment per a seleccions parcials)
  • .values_list('camp', flat=True) — retorna una llista plana de valors d'un camp
  • .distinct() — elimina duplicats (SELECT DISTINCT)
  • .none() — QuerySet buit sense consulta SQL; útil en lògica de permisos
📌 Lazy evaluation

Un QuerySet no executa cap SQL fins que no es força la seva avaluació: iteració amb for, conversió a llista (list(qs)), accés per índex (qs[0]), comprovació booleana (bool(qs)) o representació (repr(qs)). Gràcies a això pots construir consultes complexes encadenades sense penalització de rendiment fins al moment necessari.

◆ Lookups de camp — filtres avançats

Els lookups s'especifiquen com a keyword arguments als mètodes filter(), exclude() i get() usant la convenció nom_camp__lookup=valor (doble guió baix). Cada lookup es mapeja a un operador SQL diferent.

Les relacions es travessen amb el doble guió baix seguint el nom de la relació: filter(autor__cognoms__icontains='rodoreda') busca llibres de la Mercè Rodoreda. Django genera automàticament el JOIN necessari.

◆ Q(), F(), annotate() i optimitzacions

Per a consultes més complexes, Django ofereix tres eines fonamentals: Q() per a condicions OR i AND combinades, F() per a comparar o operar entre camps del mateix model sense carregar-los a Python, i les funcions d'agregació (Count, Sum, Avg…) per a annotate() i aggregate().

  • Q(condicio1) | Q(condicio2) — OR lògic entre condicions
  • Q(condicio1) & Q(condicio2) — AND explícit (equivalent a arguments separats per coma)
  • ~Q(condicio) — NOT lògic
  • F('camp') — referència a un camp de la BD; evita race conditions en actualitzacions concurrents
  • F('preu') * 1.21 — operacions aritmètiques entre camps directament a la BD
  • annotate(alias=Func(...)) — afegeix una columna calculada a cada objecte del QuerySet
  • aggregate(nom=Func(...)) — retorna un diccionari amb el valor agregat de tot el QuerySet
  • select_related('rel') — JOIN SQL per a ForeignKey i OneToOne; carrega relacions en una sola consulta
  • prefetch_related('rel') — consultes separades + join en Python; per a ManyToMany i reversos de ForeignKey
⚠️ El problema N+1

Sense select_related o prefetch_related, accedir a una relació dins d'un bucle genera una consulta SQL per a cada objecte (problema N+1). Per exemple, iterar 100 llibres i accedir a ll.autor.nom genera 101 consultes. Amb Llibre.objects.select_related('autor') se'n genera només una.

Python consultes_avancades.py — Q, F, annotate, select_related 
from django.db.models import Q, F, Count, Sum, Avg, Max, Min
from django.utils import timezone
from datetime import timedelta
from books.models import Autor, Llibre, Lector, Prestec


# ── Q(): condicions OR ────────────────────────────────────────────────
# Llibres disponibles O reservats (dos estats vàlids per a mostrar al catàleg)
al_cataleg = Llibre.objects.filter(
    Q(estat='disponible') | Q(estat='reservat')
)

# Autors nascuts als anys 40 O catalans
autors_especials = Autor.objects.filter(
    Q(data_naix__year__range=(1940, 1949)) | Q(nacionalitat='CAT')
)

# Llibres que NO estan de baixa (NOT amb ~Q)
actius = Llibre.objects.filter(~Q(estat='baixa'))

# Combinació complex: (disponible I >200 pàgines) O (reservat I autor català)
combinat = Llibre.objects.filter(
    (Q(estat='disponible') & Q(pagines__gt=200)) |
    (Q(estat='reservat') & Q(autor__nacionalitat='CAT'))
)


# ── F(): operacions a nivell de base de dades ─────────────────────────
# Préstecs on la data límit és anterior a la data de préstec + 14 dies
# (detecta límits inusualment curts)
curts = Prestec.objects.filter(
    data_limit__lt=F('data_prestec') + timedelta(days=14)
)

# Actualitzar en bulk: ampliar tots els préstecs actius 7 dies
# F() evita la race condition que tindríem si llegim i escrivim en Python
Prestec.objects.filter(
    data_devolucio__isnull=True
).update(data_limit=F('data_limit') + timedelta(days=7))


# ── annotate(): afegir columna calculada a cada objecte ───────────────
# Quants llibres té cada autor? (annotate afegeix 'total_llibres' a cada Autor)
autors_amb_total = Autor.objects.annotate(
    total_llibres=Count('llibres')
).order_by('-total_llibres')

for autor in autors_amb_total:
    print(f"{autor} — {autor.total_llibres} llibres")

# Lectors amb el nombre de préstecs actius
lectors_prestecs = Lector.objects.annotate(
    prestecs_actius=Count(
        'prestecs',
        filter=Q(prestecs__data_devolucio__isnull=True)
    )
).filter(prestecs_actius__gt=0)

# Autors amb el nombre de pàgines total dels seus llibres
autors_pagines = Autor.objects.annotate(
    total_pagines=Sum('llibres__pagines')
).filter(total_pagines__isnull=False)


# ── aggregate(): valor únic per a tot el QuerySet ─────────────────────
# Estadístiques de la biblioteca
stats = Llibre.objects.aggregate(
    total=Count('id'),
    disponibles=Count('id', filter=Q(estat='disponible')),
    max_pagines=Max('pagines'),
    avg_pagines=Avg('pagines'),
)
# Retorna: {'total': 150, 'disponibles': 87, 'max_pagines': 1200, 'avg_pagines': 312.5}

print(f"Total: {stats['total']}, Disponibles: {stats['disponibles']}")


# ── select_related(): JOIN per a ForeignKey i OneToOne ────────────────
# SENSE select_related: 1 + N consultes (problema N+1)
# for ll in Llibre.objects.all():
#     print(ll.autor.nom)   # <-- nova consulta per a cada llibre!

# AMB select_related: 1 sola consulta amb JOIN
llibres_autor = Llibre.objects.select_related(
    'autor'       # join amb la taula d'autors
).filter(estat='disponible')

for ll in llibres_autor:
    print(f"{ll.titol} — {ll.autor.nom_complet()}")  # cap consulta addicional


# ── prefetch_related(): per a ManyToMany i reversos ───────────────────
# SENSE prefetch: 1 consulta per als autors + 1 per als gèneres de cada llibre
# AMB prefetch: 1 consulta per als llibres + 1 per a tots els gèneres
llibres_generes = Llibre.objects.prefetch_related(
    'generes'     # M2M: genera 2 consultes totals, no N+1
).filter(estat='disponible')

for ll in llibres_generes:
    gens = ', '.join(g.nom for g in ll.generes.all())  # usa la cache de prefetch
    print(f"{ll.titol}: {gens}")


# ── Encadenament complet: filtre + annotate + select_related ──────────
# Els 10 autors més actius dels darrers 6 mesos, amb el nom complet
sis_mesos_enrere = timezone.now() - timedelta(days=180)

top_autors = (
    Autor.objects
    .annotate(
        prestecs_recents=Count(
            'llibres__prestecs',
            filter=Q(llibres__prestecs__data_prestec__gte=sis_mesos_enrere.date())
        )
    )
    .filter(prestecs_recents__gt=0)
    .order_by('-prestecs_recents')
    [:10]   # LIMIT 10 — s'aplica a la BD, no en Python
)
🔮 update() i delete() en bulk

Per a actualitzar o esborrar molts registres d'una vegada sense carregar-los a memòria, usa QuerySet.update(**kwargs) i QuerySet.delete(). Generen un sol UPDATE o DELETE SQL. Atenció: delete() en bulk no crida el mètode delete() de cada instància ni dispara signals post_delete.

from django.db.models import Count, Sum, F
from books.models import Llibre, Prestec

# 1. Prestecs retornats abans de la data prevista
retornats_aviat = Prestec.objects.filter(
    estat='retornat',
    data_retorn_real__lt=F('data_retorn_prevista')
)

# 2. Total de pàgines disponibles
total_pagines = Llibre.objects.filter(disponible=True).aggregate(
    total=Sum('num_pagines')
)
# Resultat: {'total': 12450}

# 3. Nombre de llibres per autor
llibres_per_autor = Llibre.objects.values('autor__cognoms').annotate(
    total=Count('id')
).order_by('-total')

# 4. Llista plana de títols
titols = list(Llibre.objects.values_list('titol', flat=True))
# Resultat: ['El nom de la rosa', 'Tirant lo Blanc', ...]
